# Interfaces & Composition Layer (`src/interfaces/`)

## Purpose

`src/interfaces/` is the outer presentation, CLI, local dev middleware, and dependency-wiring shell of **Uplift**:

- **`cli/queryLogs.ts`**: Command-line utility (`npm run logs:query`) for filtering active and compacted session logs by `--level`, `--category`, `--actor`, `--actee`, `--action`, `--min-tick`, `--max-tick`, and `--has-ai-reasoning`.
- **`vite/localDiskBridgePlugin.ts`**: Vite dev-server middleware mounting `/api/telemetry/*`, `/api/saves/*`, `/api/scene-blueprints/:stageId`, and `/api/character-visuals/:characterId` with a `256 KiB` body cap (`413`), path-traversal rejection, confined visual asset reads/writes through the shared infrastructure helper, exclusive temporary-file replacement, and Zod `safeParse` validation (`400`). It injects a per-run 256-bit bridge token into dev HTML; production HTML contains no token.
- **`three/`**: Three.js 60 FPS WebGL stage-paint chiaroscuro scene graph & parametric kitbash builders (`StageKitbashBuilders.ts`, `ChiaroscuroStageRenderer.ts`), featuring a shared 3-band stepped toon gradient `DataTexture`, parametric architectural motifs, character posture/wardrobe kitbashers, `userData.semanticId` tagging, raycast lookup, and `disposeSceneGraph`. Travel-cabin rendering and surface-cue contracts remain [planned design](../../DESIGN_NOTES.md).
- **`hud/`**: In-Game `F3` Stage, Lighting & Wardrobe Inspector controller and Agent DOM Mirror (`StageInspectorDomMirror.ts`) synchronizing `data-active-space-id`, `data-hovered-semantic-id`, `data-selected-semantic-id`, `data-debug-paused`, `data-camera-mode`, and `globalThis.__UPLIFT_STAGE_INSPECTOR__`, plus pure live blueprint mutators.
- **`composition/`**: The only page. Root `index.html` loads `composition/browserMain.ts`. `shellDocument.ts` stacks `viewport`, an empty `diegetic` layer, and `dev-hud`. `browserMain.ts` creates one `WebGLRenderer` (`antialias: false`, `alpha: false`), caps the pixel ratio at `1`, and calls `PlaySession.frame` once per animation frame. `playInput.ts` routes development waypoint commands, floor and portal pointers, pause, and free-cam. These are dev tooling, not the planned player movement/use interface. `stageLabPanel.ts` is the paused stage panel. The proving-slice pack is named only in the startup call at the bottom of `browserMain.ts`.

## Visual asset storage

Stage and character JSON stay under their separately configured roots. Reads and writes reject symlinks in roots, parents, destinations and temporary paths, including dangling links. GET checks the confined file size before reading, returns 404 for missing assets and creates no directories. A valid PUT creates missing directories through checked ancestors, validates schema and URL/payload ID agreement, and atomically replaces the destination using an exclusively created temporary file. Rejected links and failed replacements preserve outside files and the previous saved asset.

`handleLocalDiskBridgeRequest` performs local I/O for the Vite middleware. Its optional sixth filesystem-dependency argument supports real-directory fault tests and is never populated from HTTP input. Direct dispatcher tests establish storage and schema behavior; they do not establish network request authorization.

## Browser save feedback

The dev page receives `meta[name="uplift-bridge-token"]`, generated with local cryptographic randomness for each server run and renewed on restart. The browser transport reads it at save time and sends `X-Uplift-Bridge-Token` with JSON on the existing relative stage/character PUT routes. Requests require the same origin and reject redirects. The production build has no injected token.

The Save stage control and callable `saveVisual` API keep their void callback contract. Each explicit attempt is sent once, in order; failures are not replayed automatically. A missing token or 403 response requests a page reload, while network and other HTTP errors report a readable failure. Edits stay in memory through failed saves. The transport never renders response bodies, exceptions or token values.

`browserMain` owns a dedicated `data-bridge-save-status` paragraph with `role="status"`, `aria-live="polite"` and `aria-atomic="true"`. Its text changes from Saving to Saved or an error and persists until the next explicit attempt. It is separate from per-frame play status. Sending the token is client behavior; this transport does not enforce server authorization.

## Local HTTP bridge

The dev server binds to `127.0.0.1:5173` with `strictPort`. CORS and the bridge share an immutable policy bound to the actual TCP port, including ephemeral ports in tests. Only exact `localhost:<port>` and `127.0.0.1:<port>` Host values and their `http://` Origins are accepted. With no Origin, `Sec-Fetch-Site` must be `same-origin` or `none`. Forwarded headers cannot grant access. Reads also require this provenance; every POST, PUT and DELETE additionally requires the current `X-Uplift-Bridge-Token` and `application/json` (optional UTF-8 charset). Reload the page after a restart to refresh its token. This protects against browser-origin attacks; it does not authenticate local OS users.

Only telemetry session/batch/compact POSTs, save-list GET, save-slot GET/PUT/DELETE and stage/character GET/PUT routes dispatch. Duplicate security headers, unknown paths and unsupported methods are rejected before body buffering. The 256 KiB default cap counts bytes; excessive declared lengths are rejected immediately, and streams are destroyed on the first excess chunk. Aborted bodies never dispatch. Middleware-only and non-TCP hosting are unsupported; before listening or after close the policy denies access. A request is tied to its originating server run and cannot dispatch after a restart, even if its body began arriving earlier. The old run is retired before replacement configuration begins, including fresh-policy config reloads and concurrent restarts. If replacement fails, bridge access stays unavailable until a successful restart. Each successful Vite restart starts a fresh current query; logger construction during replacement rotates the previous logs.

Errors expose stable JSON messages: 400 for invalid requests or unsafe storage paths, 403 for denied provenance/token, 404 for missing routes/resources, 405 for unsupported methods, 413 for excess bytes, 415 for non-JSON writes, 500 for storage failures and 503 for unavailable storage. Filesystem details and tokens are never returned. A path-policy rejection, including during session start, returns 400. Other failed explicit telemetry session starts return 500. Either initialization failure disables batch/compact with 503 until an authorized explicit session retry succeeds. Constructor failure aborts server setup. `maxPreviousSessions` is a positive integer, defaults to three, and controls logger retention independently of request size.
