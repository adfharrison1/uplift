# Agent Guide — Content & Plug-and-Play Modules (`src/content/`)

## Strict Guardrails (Enforced by `npm run verify`)

1. **Topology vs 3D Presentation Split**:
   - Files in `src/content/` (outside `src/content/scene/`) are **pure domain content**: they may import from `src/domain/` only and must NEVER import `src/application/`, `src/infrastructure/`, `src/interfaces/`, or `three`.
   - Files in `src/content/scene/` define 3-Layer Encoded Visual Blueprints (`EpochVisualTheme`, `StageSceneBlueprint`, `CharacterVisualBlueprint`) for the renderer and may import from `src/interfaces/three/`, `src/domain/`, and `three` (and must NEVER import `src/application/` or `src/infrastructure/` directly).
2. **Deterministic & Immutable Content Only**: `Math.random()`, `Date.now()`, `performance.now()`, and `new Date()` are forbidden across all files in `src/content/` (enforced by ESLint and `layer_boundaries.test.ts`). Deeply freeze exported blueprint constants so runtime callers cannot mutate shared content definitions in place.
3. **Typed Plugin State & Configurable Epochs**: When a behavior, crisis thread, office, or mechanic needs custom state on `WorldState`, declare a `StateSliceKey<T>` via `defineStateSlice<T>(id, defaultValue)`. Never hardcode a fixed number of Epochs—always treat the campaign Epoch sequence as a configurable `EpochProfileBlueprint[]` list (`Epoch` === `Era`).

## Recipes for Adding / Swapping Modules

- **Add a Character or Rival Operative**: Create a `CharacterBlueprint` or `RivalCivBlueprint` (specifying tier, `lineageId`, `inertiaPillars`, and `emergencyVice`), and add a matching `CharacterVisualBlueprint` in `src/content/scene/` keyed by `characterId` and `lineageId`.
- **Add an Office, Quiet Claim, Thread, or Orbital Pass**: Register an `OfficeBlueprint`, `QuietClaimBlueprint`, `TrajectoryThreadBlueprint`, or `OrbitalPassBlueprint` in an `EpochModulePackInput` via `EpochModuleRegistry` — never add hardcoded switch statements to `src/domain/`.
- **Add an Indoor Room, Outdoor Area, or Off-Stage Region**: Add the logical `SpaceNodeBlueprint` to the epoch pack, and (for visible 3D stages) add a `StageSceneBlueprint` with deterministic wall/prop/light `semanticId`s and `CameraVolumeBlueprint`s in `src/content/scene/`. Optional `neighborWaypointIds` stay inside one space. A portal prop sets both target ids and `portalState`; mark the matching stage prop `isPortal: true`. `separationWeight` `0` keeps a packed group on its authored spacing. Exemplar names such as the starter hold stay in content. The proving slice is `worlds/starterHoldPack.ts` plus `scene/starterHoldStages.ts`. A visible body needs a `CharacterVisualBlueprint` whose `characterId` matches that character. The renderer skips a pose with no matching visual.
- **Add an Epoch 2+ Travel Route or Cabin Surface Cue**: Register a `VehicleKindBlueprint` (with `travelTechTier` within that Epoch's `maxTechTierForEpoch`), `TransitRouteBlueprint`, `TravelVignetteBlueprint`, and optional `EnRouteEncounterTable` in the epoch pack. Pair it with a bounded `vehicle_cabin` `StageSceneBlueprint`. Author live immersion as `TravelSurfaceCueBlueprint`s that bind small kitbash `semanticId` deltas (mud, extra gazette, empty seat, blackout shutters) to world-state predicates — never per-frame, never as a HUD. Epoch 1 has no travel vignettes.
