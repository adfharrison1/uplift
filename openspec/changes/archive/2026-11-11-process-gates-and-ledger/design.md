# Design

## Context

See proposal.md for motivation and scope. The handoff, register owner decisions, S7 rulings and binding punch list are the authority for the documentation work. The existing roadmap is ordered, but no command validates its graph or selects next work. The ledger and archive wrapper do not exist. Existing architecture tests already enforce structural skill checks without prose pinning. The current archive CLI performs spec synchronization and rollback itself; pre-syncing an ADDED requirement and then invoking full archive would fail as a duplicate.

The current checkout contains tracked historical reviews despite earlier instructions calling them ignored. Preserve them. Future review storage follows the later tracked-history precedent as a reviewable assumption; this choice does not change runtime behavior or ledger durability. Historical evidence is not rewritten to satisfy live-guidance citation checks.

The config instruction to repeat a dated pinned-version/CVE table conflicts with the owner's later single-source decision. Use package.json and .nvmrc as canonical sources instead. Observed during planning: Node pin 24.22.2, engine >=24.0.0, native TypeScript 7.0.2, compatibility TypeScript 6.0.2, Three 0.186.1, Vite 8.3.5, Vitest 5.0.5 and YAML 2.9.1. These are provenance, not a new maintained version table; implementation reads the manifests.

## Goals / Non-Goals

**Goals:** reproducible local status operations; explicit evidence and reversible decisions; green intermediate commits; preservation of owner wording and historical findings; no-loss document consolidation; enforcement that catches structural drift without claiming to understand prose.

**Non-goals:** gameplay changes, new dependencies, cloud tooling, arbitrary task automation, automatic approval, automatic commits, hidden deletion of unresolved findings or rewriting old archive evidence. No simulation layer is modified. Tooling stays in scripts and tests; skills and documents remain repository guidance.

## Decisions

### 1. Delivery and document workflows

Create uplift-review-gates and root-and-branch-review skills, with procedural reference documents where useful. Root AGENTS becomes a short shipped-code guide linking every project skill, including the six OpenSpec skills. Preserve the default-worktree instruction in root guidance and the apply skill. A skill regeneration check must retain it.

The gates skill retains all existing 3/2/6 independent reviews and adds G1–G6. G2 security and G4 failure containment are named adversarial axes, G3 hot-path work is a performance axis. G1 records actual entry point, producer, consumer and observable result; G5 reconciles ledger state; G6 maps every scenario to a named test or explicit manual evidence. Unsupported or unrun evidence is reported as such. Reviewer findings are independently checked before fixes; every finding has a disposition. The owner still approves each task before commit. New findings become recorded tasks when they need an unplanned fix.

The periodic skill encodes the actual slices 0–7, two or three scouts, two blind challenges per finding AND recommendation, a third for critical/roadmap-changing items, lead verification, blunt owner checkpoints, rejected-decision retention and the revise/four-review/rulings/revise/two-review/punch-list sequence. No mandatory playtest is invented at baseline. Preserve rule/vocabulary/placeholder/code tags and de-weighted topics. Phase 1 uses approved content batches before a separately traced restructure; use the default checkout under the latest worktree policy. Briefs say “high reasoning, medium-to-high model”, including fidelity/usability reviewers for this skill. Slot limits mean independent review briefs may run in waves, never fewer reviews.

Copy and repair the existing quotechecker inside the periodic skill. Check full quoted ranges, preserve source line semantics, reject malformed/missing/escaping paths including symlink escapes, return nonzero for mismatches and leave cmd evidence for explicitly recorded manual verification. It never runs evidence commands. Explicit --root defaults to discovered repository root; no personal path remains. Tests use isolated files and exercise matching multiline quotes, wrong tails, wrong ranges and containment.

All three doc-editing skills share the integrity procedure: system placement; one canonical statement; status index, Where-facts-live, roadmap and dispositions checked on every edit; owner language verbatim; no-loss mapping for moves; two independent fidelity/coherence reviews; budgets and pillar/rules-spine checks. A check with no required edit is recorded as unchanged. The design-notes rewrite retains topic research with three independent game-design, code-fit and pacing/hardware perspectives, but never writes AGENTS. Unfamiliar names are researched. Failed, undecided or unprocessed inbox text remains. Exercise on the real “single further out zoom” inbox note, reconciling existing coverage without inventing another decision; inbox removal waits for the applicable owner approval.

### 2. Truthful guidance and no-loss migration

Before cutting config context, build a paragraph/block mapping from its current text to retained content, a canonical design home or an explicitly superseded decision. Two reviewers must pass fidelity and coherence first. Move necessary unique content into DESIGN_NOTES or indexed design files; preserve owner exemplars verbatim. Then reduce context below 1,500 whitespace-delimited words and replace unsupported operations.propose guidance with supported artifact rules. Consumer-ending scenarios, call-site lists, MODIFIED deltas and the size rule live in those rules. Versions and CVE attestations become manifest pointers.

Root AGENTS targets about 900 words, ceiling 1,050. Remove unshipped locomotionMode, interactionHold, proximity/arrival/paging, eval command and model-worker claims. Describe schema-only registry kinds and reducer contracts precisely; don't claim a missing runtime where a reducer already exists. State that the logger/compactor exist but the browser is not yet wired. Fix debug skill CLI, compaction and trace claims against actual shipped paths. Preserve layer rules, verify/hook behavior, deterministic simulation, local operation and section-guide links.

Update both README and AGENTS in affected domain, application, infrastructure, interfaces and tests sections, plus root README/AGENTS. Content guidance is inspected and updated only if an affected factual claim needs correction. The specific carryovers are the stale ONNX/free-text/setup-models claims, infrastructure model weights and interface “click-to-waypoint” presentation. Do not build the deferred pack-loader or blueprint contracts to make docs true.

DESIGN_NOTES retains its aspirational ~14k target; the existing ~16.9k baseline is not a failing hard ceiling. The engineering split remains deferred until M1. New feature files need status-index rows; design/README.md is a navigation index and is exempt from a feature row. Keep status and Where-facts-live pointers coherent. Correct only evidenced roadmap debris: settled Q3, moved graph scope, M5 stub end-card claim, already shipped bridge-test wording and this proposal's capabilities/status. Do not reorder the roadmap.

### 3. Shared local state module

Use scripts/project-status.mjs as a reusable module and CLI. Reuse YAML 2.9.1, Node built-ins and JSDoc types where helpful; add no runtime dependencies. It exports pure validation/selection/transition functions and filesystem adapters for CLI, archive and tests. Tests use isolated temporary repositories; never operate on the live ledger. Expand lint scripts to cover scripts/*.mjs. Architecture tests import the pure checker rather than spawn npm or recursive verify.

Commands (examples use placeholder IDs):

```text
npm run roadmap:next -- --json
npm run defects -- list --status open --json
npm run defects -- list --include-resolved --json
npm run defects -- add --file <record.json> --expect-ledger-revision <n>
npm run defects -- transition <id> --to in_progress --expect-revision <n> --reason <text>
npm run defects -- transition <id> --to blocked --expect-revision <n> --reason <text> --blocker <text>
npm run defects -- transition <id> --to parked --expect-revision <n> --reason <text> --revisit-when <text> --owner null
npm run defects -- transition <id> --to open --expect-revision <n> --reason <text> --owner <roadmap-id>
npm run defects -- update <id> --file <patch.json> --expect-revision <n> --reason <text>
npm run defects -- reopen <resolved-id> --new-id <id> --owner <roadmap-id> --reason <text> --expect-ledger-revision <n>
npm run defects -- reconcile --check
npm run defects -- reconcile --repair --change <roadmap-id>
npm run defects -- reconcile --cancel --change <roadmap-id>
npm run change:archive -- <roadmap-id> --resume
npm run change:archive -- <roadmap-id>
```

The mutation file is data parsed from an explicitly supplied file, never executable content. A transition to verified also accepts --evidence <file.json>. Reject unknown commands/options/fields and malformed YAML including duplicate keys. List filters do not mutate. IDs use a bounded portable alphanumeric/hyphen/underscore grammar, start with alphanumeric and cannot contain path separators or dot segments. Text and JSON use stable ID ordering (roadmap selection alone uses declared order), LF output and deterministic key/event ordering; no clock or random event IDs. Success exit 0, invalid input/state/conflict exit nonzero with distinct diagnostic codes. Empty eligible sets are successful informative results; invalid graph is an error.

Roadmap validation checks ID/status/reference/milestone integrity and a linear DAG traversal. validated_by is a reference, not a dependency. Scan actual active and archive directories once per invocation. Match archive directories by stripping exactly one valid YYYY-MM-DD prefix, preserving date-prefixed original IDs. Reject duplicate archive identities and active/archive collisions. done-by-review requires a nonempty delivery reference, checked as a evidence locator or Git commit reference. An active directory makes a planned row active; proposed without an active directory and archived without an archive are errors. Actual archives with stale labels are reported as reconciliation drift, never treated as unarchived. next reports all active proposals before recommending later work, and otherwise selects the first planned entry whose dependencies are archived or evidenced done-by-review.

### 4. Defect schema and transition table

openspec/defect-ledger.yaml contains schema_version: 1, a monotonically increasing ledger revision and entries sorted by id. Each entry has id, summary, source (path plus finding/anchor and a self-contained description), severity (critical/major/minor), status, fixing_change (nullable only when parked), revision, history and current evidence. Optional parent_id and reopened_from preserve splits and recurrence. History has contiguous sequence numbers, operation, from/to, reason, previous/new owner and evidence references where changed. No wall-clock timestamps are required. Initial add creates revision 1; each successful mutation increments entry and ledger revisions once. Caller-supplied IDs are stable; duplicate active or archived IDs fail. Every history event contains enough structured before/after data to replay current status, owner, severity, blocker/revisit fields and evidence. Validation requires replay to equal the current record and its revision, rejects discontinuous or illegal historical transitions, and rejects direct field edits that disagree with history. Ledger revision advances once per successful mutation, including archive finalization; read-only output and failed operations never increment it.

| From        | Legal destinations              | Preconditions                                                                           |
| ----------- | ------------------------------- | --------------------------------------------------------------------------------------- |
| open        | in_progress, blocked, parked    | reason; live owner unless parked; blocked needs blocker; parked needs revisit condition |
| in_progress | open, blocked, verified, parked | reason; verified needs fix, passing tests and independent-review evidence               |
| blocked     | open, in_progress, parked       | reason describing resolution or deferral; clear current blocker when leaving blocked    |
| verified    | in_progress, open, blocked      | reason invalidating verification; move old evidence into history                        |
| parked      | open                            | reason, live fixing owner and cleared current revisit condition                         |
| verified    | resolved                        | archive wrapper only, after archive exists and exact receipt matches                    |
| resolved    | none                            | reopen creates a new ID linked to the immutable receipt                                 |

The transition command validates its target fields together and writes them atomically. --blocker, --revisit-when, --owner and --evidence supply destination prerequisites; entering parked without --owner retains the current live owner, while explicit null unschedules it. Leaving blocked/parked clears obsolete current-state fields automatically, retaining them in history. No-op status transitions fail instead of manufacturing history. Add accepts open or parked only. blocked stores a nonempty blocker; parked stores reason and revisit_when; other states reject stale blocker/revisit fields. update allows summary, source additions, severity, ownership, blocker/revisit details and evidence, but cannot replace IDs, status, revision or history directly. Changing a verified record's owner, summary or fix/test/review evidence requires reopening first; adding supplementary evidence can retain verification if the verified evidence is unchanged. Reassigning an unresolved defect to another live roadmap owner is explicit and reasoned, never an archive side effect. Evidence consists of nonempty fix_ref, test records (command, outcome, evidence locator) and review records (reviewer/brief, disposition and evidence locator). Evidence locators are tagged: repository-relative paths for stable repository files, or {change_id, relative_path} for files traveling with a change. Resolve the latter against the unique active or archived change directory; preserve the locator in history rather than rewriting history at archive. Reject traversal/symlink escapes and ambiguous identities. Require test/review evidence to be retained in tracked repository files, not ephemeral agent transcripts or logs. Use one consolidated task evidence report and one review record with distinct independent submissions; the tracked-evidence requirement does not require raw command transcripts. Keep routine output, retries and diagnostic scripts untracked, and consolidate before binding digests. Capture a content digest for verification evidence so a changed file invalidates its recorded verification until explicitly reviewed. Use immutable per-task evidence files once verified; later delivery summaries are supplementary records, avoiding self-hashing or repeatedly modifying a record whose digest is already referenced. Use repository-scoped commit/object references for fix_ref where available; an uncommitted fix may use a file/content digest and is bound to its delivered commit in the closing record. Validate shape, resolution and digest; do not claim that this proves semantic correctness or rerun arbitrary evidence commands.

The active seed is built from the reconciliation inventory: all accepted current code defects, including minor ones, with split child IDs when owners differ. Process/document findings receive explicit disposition in that inventory instead of being silently dropped or mislabeled runtime defects. Already archived fixes are excluded with delivery evidence. S3-16 remains parked until a room has 100+ bodies. No owner is invented for deliberately deferred work. The newly reproduced Git fixture environment defect belongs here. A seed entry fixed by an earlier task of this change still enters with history and is transitioned to verified using its recorded evidence.

### 5. Serialized writes and recoverable archive

All supported mutations acquire one exclusive project lock under openspec, using exclusive creation and owner metadata; contention fails promptly. A stale lock is not silently stolen: the recovery command reports its owner and requires explicit inspection/removal once no writer remains. Validate file/parent containment and reject symlinks. Read current bytes under the lock, validate expected revision, prepare a complete candidate in the same directory and rename atomically. Recheck input hashes before replacement to catch direct edits observed since reading. This serializes supported writers; arbitrary editors ignoring the lock cannot be made transaction-safe. Record that limit instead of claiming a universal filesystem transaction.

The archive wrapper uses the same helpers and lock. Before any preparation, query OpenSpec context/list/status and require their resolved planning home and change root to match this repository and its intended active change. Reject declared or global external stores with an actionable diagnostic; this project wrapper does not perform cross-store transactions. Recheck the resolved root before invoking archive; never assume cwd alone selects the local root. Call sites: archive skill → npm change:archive → wrapper → project-status validation/receipt preparation → installed OpenSpec CLI (argument array, no shell) → archive receipt consumer → ledger/roadmap finalization → combined list/reconcile. Normal archive performs full CLI spec synchronization exactly once. Do not manually sync then run full archive, and do not pass --no-validate or --skip-specs. If specs were already synced manually, stop with a diagnostic requiring inspection rather than guessing. Inspect CLI status/instructions to identify task completion; avoid hardcoding only tasks.md when another schema is selected.

Preflight requires a valid graph/ledger, completed required tasks, recorded final reviews and strict OpenSpec validation. All defects owned by the change must be verified. A parked defect still assigned to it blocks archive. Write a prepared defect-resolution.yaml into the active change, containing schema version, original change ID, exact record snapshots/hashes, ledger base revision and expected roadmap row fingerprint; it travels with the archive. Write a small tracked openspec/archive-transaction.yaml journal with the operation, preimages and target digests. Only one transaction exists at a time. Reconciliation fails while it is pending. An empty receipt is allowed for changes with no defects.

Invoke OpenSpec archive with validation and noninteractive confirmation after the workflow's owner approval. Even on nonzero CLI exit inspect actual state: if no archive exists, preserve active entries and prepared evidence; if archive exists, treat the operation as pending finalization. Conflicting or duplicate archive destinations fail closed. Never rerun archive when the receipt has already moved.

After successful move, deterministically finalize the receipt's terminal records, remove only exactly matching active snapshots, update the roadmap status to archived and retain the archive evidence reference. Journal each intended before/after digest so interruption between ledger and roadmap writes is recognizable. The prepared receipt's location plus journal establishes pending resolution; combined listing reports a distinct pending-finalization diagnostic with the affected IDs until finalization is complete; it never temporarily omits defects whose active rows have already been removed. A successful run removes the journal last and exits zero only after reconciliation passes.

--repair accepts each affected file only at its recorded before or after digest and advances missing steps. Repeating repair on completed state is a no-op. Revision/content conflicts, missing receipts or archives without wrapper evidence are reported for manual evidence-backed recovery; do not remove entries simply because a directory exists. Recovery is a separate dispatch path before normal preflight. For a prepared transaction with no archive and an intact active change, --cancel verifies all affected files at their preimages, removes only that transaction's generated receipt/journal and leaves every defect unchanged; it records the cancellation in command output and permits subsequent mutations. Preserve any preexisting receipt bytes recorded in the journal. If the underlying CLI left spec edits, a missing active directory or any differing bytes, cancellation refuses and reports those conflicts instead of reverting them blindly. --resume on change:archive validates the same intact state, refreshes strict validation and review prerequisites, and continues the existing transaction without making another receipt. When the archive already exists, --resume delegates to --repair; --cancel refuses once the move has occurred. Crashes before the journal is written leave only a prepared receipt: verify its recorded preimages before explicitly resuming or canceling it. Test cancellation and resumption after each pre-move failure, including failed strict validation, and prove an unrelated mutation works after cancellation. An unrelated supported mutation is blocked while a transaction is pending. Unsupported external edits are preserved and require an explicit resolution. A bypass archive with unresolved entries fails docs-truth and cannot silently satisfy the ledger. Archived receipts are immutable after finalization; reopens create successor records.

This journal is chosen over best-effort two-file writes because a crash between ledger and roadmap edits otherwise loses reliable retry information. It is small and local, not a database or background service. Tests inject failures around each receipt/journal/CLI/ledger/roadmap boundary and assert actual consumer output and byte preservation.

### 6. Documentation checks and verification

Add tests/architecture/docs_truth.test.ts last. Use typed pure checking helpers with small positive and negative fixture trees. Resolve root backticks by category: repository paths and skill links; npm scripts; exported/type declarations indexed from source; explicit language/config builtins. Ordinary values and key names are checked in their stated contexts, not all accepted by a blanket allowlist. Unknown technical claims produce a useful diagnostic. Keep a small explained builtin vocabulary and fixture-test rejection of plausible missing names. Numeric assertions map to actual exported constants; the planned seven-epoch ladder has no shipped constant and belongs only in design.

Scan maintained documents and source/test comments for exact known change IDs and numbered Change references, excluding OpenSpec workflow commands and ordinary uses of the verb. Allowed homes are openspec, DESIGN_NOTES and design; explicitly document historical reviews as immutable evidence. This is a proposed policy clarification, not a hidden exclusion. Do not scan ignored dependency/build output or .git; synthetic test IDs are constructed without real change citations. Every project SKILL.md must be linked from root AGENTS and each linked path must exist; retain metadata and .cursor prohibition. Include the Claude symlink target check.

Version checks compare concrete README claims to package.json, or accept pointers. Check .nvmrc against the supported engine constraint, not literal equality to its range. Planned IDs resolve to roadmap entries, not necessarily active directories. docs-truth invokes pure graph/ledger/reconciliation checks in memory. Keep every existing layer, zero-any, random/time and section-presence assertion; do not pin skill wording.

VerifyRunner.test.ts must remove inherited repository/index/worktree/object/config override Git environment from child fixtures while preserving normal PATH and required process settings. Test with a foreign index sentinel and temporary repository, proving both commit success/failure and preservation of parent Git state. This fixes the defect observed in the archived verification record, rather than weakening hooks.

Tests remain headless and local. Run targeted Vitest/Python checks and npm run verify after each task. Full verify needs loopback permission for existing HTTP tests. Closing verification records test count and observed timing against the reference budgets, runs strict OpenSpec validation, archive/reconcile fixture recovery and the existing serial command once for coverage parity. No flaky wall-clock assertions or new smoke command. Map every delta scenario to a test or named manual review result; missing coverage is a delivery blocker.

## Risks / Trade-offs

- Many documents change → six cohesive tasks, source/tooling file caps, docs carried with their owning capability, no-loss proof before cuts and independent fidelity/coherence review.
- Status can be structurally valid but factually stale → required task and closing reconciliation plus test/review evidence; no claim that a YAML validator proves the fix.
- Crash during archive → durable journal and exact receipt snapshots, failure injection and idempotent explicit repair.
- Direct editors bypass the lock → hash checks and reported conflicts; no automatic deletion on ambiguous state.
- Quotechecker uses Python → isolated targeted Python tests; keep ordinary Node verify free of a new mandatory Python runtime dependency.
- Additional checks consume verification budget → one bounded repository scan, reuse parsed documents, no subprocess-per-symbol or repeated full verification inside tests; record measured impact.

## Migration Plan

Implement skills first, then document correction, local state tooling, archive integration and finally enforcement. During tasks 1–3 only, the new gates record defect dispositions and evidence in this change's finding inventory because the command is not yet shipped; this is an explicit bootstrap stage, not a skipped gate. Task 4 migrates those records through add/transition commands and checks parity. From task 4 onward apply and closing reviews require the real reconciliation command. Keep all intermediate commits green. Seed and independently review the finding inventory before enabling docs-truth. Once shipped, apply and archive workflows use the checked commands, while old completed archives remain valid without retroactive receipts. Receipt discovery distinguishes those old archives from newer wrapper-managed operations using the receipt/journal protocol, not an arbitrary calendar cutoff. Seed a finite legacy_archives list in ledger metadata from the pre-tooling archive directory inventory. Supported mutation commands cannot expand that exemption. Every other archive must have a v1 receipt, including zero-defect archives, and its roadmap row retains archive_receipt plus archive_protocol: v1. Validate both references and require the discovered archive to be either in the exact legacy set or receipt-managed. Thus deleting a finalized receipt remains an error even after its active entries disappear. Preexisting archives are not rewritten. Rollback before use is an ordinary revert; after a receipt exists, preserve ledger/history data and use explicit reconciliation before reverting tooling. Do not roll back by deleting evidence.
