# Proposal audit and document integrity

Three independent, read-only proposal audits used high-reasoning, medium-to-high-model briefs. Each reviewed the draft without seeing the other initial reports. Dispositions below are planning-artifact corrections; no runtime defect is claimed fixed.

The completeness auditor also obtained two independent read-only source checks. Their additional findings are recorded after the required three lenses.

| Reviewer / lens | Finding | Disposition and source check |
| --- | --- | --- |
| `save_proposal_arch` / architecture, adversarial, determinism and hardware | Inner snapshot `epochId` and `worldTick` could disagree with the outer envelope. | **Accepted.** The existing coordinator shallow guard checks neither equality (`SimulationCoordinator.ts`, `isSerializedWorldStateSnapshot` and `loadFromSlot`). Codec, listing, task 1.1/1.2 and spec scenarios now require both checks, atomic rejection and unchanged slot bytes. |
| `save_proposal_arch` / same lens | Prop `state` could lose non-JSON values when written. | **Accepted.** `PropSimulationState.state` is `Record<string, unknown>` and file persistence uses `JSON.stringify`. Codec encode/decode and tests now require lossless plain JSON, including rejection of `NaN`, `undefined`, BigInt and cycles. |
| `save_proposal_arch` / same lens | Listing would miss malformed custom slices, version maps and legacy state. | **Accepted.** Current envelope validation uses `unknown` slice values and a loose legacy record; coordinator validates them during load. The proposal now requires context-free structural validation in listing and states that registered-slice compatibility remains a coordinator check. |
| `save_proposal_complete` / completeness, design alignment and atomicity | `readable` could imply a coordinator load would succeed. | **Accepted.** The spec and design define repository-structural readability, with a registered-slice rejection scenario. |
| `save_proposal_complete` / same lens | Unreadable reason precedence and synthetic version-one migration were underspecified. | **Accepted.** Design and spec now fix classification order and define version one as the exact serialized-world field set with marker `1`, migrated by replacing only that marker on a fresh value. |
| `save_proposal_complete` / same lens | Public direct registry methods could mutate a bound pack without a declared import. | **Accepted.** `EpochModuleRegistry` exposes direct registration methods used by focused tests; production composition calls `registerPack`. The registry delta and task 2.1 now reject direct mutation after binding and binding after prior direct population, while keeping unbound direct registration. |
| `save_proposal_complete` / same lens | Exact pack-version matching needs the rollback boundary stated. | **Accepted.** The latest owner answer limits rollback to earlier campaign states under the current pack version. A matching earlier-tick and older-version rejection scenario now make that boundary testable. |
| `save_proposal_game` / game standards, safety, extensibility and document fidelity | Exact version matching conflicts with the earlier “Loading ANY earlier save” wording in `DESIGN_NOTES.md` and the roadmap. | **Superseded by the owner's later clarification.** The owner explicitly selected “Current pack version only”; exact matching implements that decision. The earlier wording remains untouched as historical owner text, and the narrower decision is recorded in this proposal. |
| `save_proposal_game` / same lens | Listing could call a malformed legacy/custom-slice slot readable. | **Accepted.** Context-free structures now receive listing checks; registered-slice schema and migration failures remain atomic coordinator-load failures. |
| `save_proposal_game` / same lens | The HTTP list route has no expected pack context, so it cannot return pack mismatch reasons. | **Accepted as scope clarification.** `localDiskBridgePlugin.ts` calls `listSlots()` without identity. The design now says the route returns structural reasons only; expected-identity reasons are port behavior for a future caller, tested directly. |
| `save_proposal_complete` / same lens | The design claimed validation never runs per frame. | **Accepted.** `RenderFrameBuilder` already invokes semantic-ID formatting per frame. The design now says this change adds no new frame-path check. |

Task 2.2 and a save scenario now require owned input and return copies with mutation tests. |
| `save_proposal_complete/save_arch_audit` / extra architecture source check | Direct registration, envelope/tick equality and per-frame wording need correction. | **Accepted as independently confirmed duplicates** of the required auditors' findings above; the registry, codec and frame wording were revised. |
| `save_proposal_complete/save_complete_audit` / extra completeness source check | Task 3.1 would exceed the three-source-file cap after the domain-barrel export. | **Accepted.** Task 1.1 now defines and exports the shared validator while already touching the barrel; task 3.1 applies it in three source files. | `save_proposal_complete/save_complete_audit` / extra completeness source check | Listing and loading could each run the pure migration, making “once” ambiguous. | **Accepted.** The design now says once per decode, and task 1.2 requires a counted real load followed by a current-version resave/load. ## Document integrity

The canonical save policy remains in `DESIGN_NOTES.md` under “State, saves and pack identity”; its status index and Where-facts-live table remain accurate for planned work. The roadmap order, dependency and scope text remain unchanged; its only edit corrects the capability path and adds the registry capability. No owner paragraph, inbox entry, design disposition or historical review was moved or cut. The narrower pack-version answer is recorded here as a later owner clarification rather than silently rewriting the earlier words. Planning contracts and audit dispositions live under this change. Shipped section guides will be updated alongside the implementation tasks. No new design file or navigation row is needed.
