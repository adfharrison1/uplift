# Design

## Context

See [proposal.md](proposal.md) for the problem. `SimulationCoordinator.saveToSlot` currently enumerates world fields into `__upliftWorldStateSnapshot`; `loadFromSlot` checks only their outer types and enumerates them again. `SaveSlotRepositoryPort` validates the outer envelope, `FileSaveSlotRepository.listSlots` silently omits corrupt files, and `GET /api/saves` returns that list. `EpochModuleRegistry` does not retain a pack identity. The browser composition uses a separate in-memory save port; it does not load disk saves into the launch. The archived slice-store contract already preserves custom values and their separate version map.

The owner confirmed there are no old local saves to preserve; no `saves/` directory or tracked save files exist. Synthetic historical **inner** snapshots will test migration, while pre-change identity-free envelopes are unsupported. The owner also clarified the earlier “Loading ANY earlier save” policy: it covers earlier campaign states under the **current pack version**, not saves from older pack versions. Preserve the original policy wording in DESIGN_NOTES and the roadmap; this change records the newer scope decision. The roadmap's `multi-session-saves` shorthand resolves to the existing `multi-session-saves-and-debug-skill` capability; the registry behavior also belongs in `modular-epoch-registries`.

## Goals / Non-Goals

**Goals:** Publish a coordinator load only after its world, RNG, slices, legacy state and pack identity have all passed validation; expose stable repository-level unreadable reasons without losing valid slots; and let the repository's durable write determine save success. Preserve deterministic results and the current headless, offline verification path.

**Non-Goals:** A player save menu, watch-boundary autosave, browser disk save loading, pack-content fingerprints, cross-pack migrations, general campaign/epoch handoff and future runtime NPC materialization. The current initial materialization and load paths must be safe; later materializers must reuse the entity-ID validator. No model or cloud service is introduced.

## Decisions

### 1. Domain codec is the single serialized-world boundary

Place `WorldStateCodec` in `src/domain/persistence/`, with a strict Zod schema for the serializable world fields and nested entity, prop, pacing, pressure, orbital, cue and scar shapes. The `WorldState` type and initial-state constructor remain in `src/domain/simulation/WorldState.ts`; the coordinator's local snapshot interface, shallow guard, save field copy and load field copy go away. The codec encodes a private plain-JSON snapshot and decodes `unknown` to a validated value; it never accepts a `StateSliceStore` or a browser object. `PropSimulationState.state` requires a lossless plain-JSON value on encode and decode, so `NaN`, `undefined`, BigInt, cycles and non-plain objects cannot disappear or change through `JSON.stringify`. The coordinator attaches custom slices only after their existing versioned restore succeeds. Unknown custom-slice IDs and versions keep their current passthrough contract.

New inner snapshots use `snapshotVersion: 2`. Synthetic version one is precisely the existing serialized-world field set with a literal `snapshotVersion: 1`; it omits no world field and permits no unknown field. The pure `1 -> 2` migration validates that shape, changes only the version marker on a fresh value, and then runs the current strict schema. An unversioned old inner snapshot is not implicitly accepted. Missing, noninteger, unsupported or future versions fail with a stable field/version diagnostic; every migration is applied at most once **per decode** and a resave writes version 2. Envelope validation and listing may invoke the pure decoder to check acceptance without rewriting raw slot bytes; a later coordinator load decodes the original bytes independently. A counted test confirms one migration call during a real load and no migration on a resave/load of current bytes. The codec requires both inner `epochId` and `worldTick` to equal their outer envelope values. A mismatch is an invalid snapshot and preserves the current coordinator state and slot bytes. This validates nested data in one place and keeps migrations local to the schema; the alternative of adding more coordinator type guards would retain duplicate lists and allow nested corruption through.

### 2. Registry identity and explicit imports precede envelope enforcement

`EpochModulePackInput` gains required `packId`, positive integer `packVersion` and an explicit list of `{ packId, packVersion }` imports. The first `registerPack` binds the registry's primary identity and target epoch; a later pack is accepted only if its identity appears in that list and its declared target epoch matches. Registration stages identity and blueprints together, so a failed import cannot partially change the registry. Existing public `registerSpaces`/`registerCharacters` and other focused registration methods can mutate an unbound registry for tests, but cannot bypass imports by mutating a bound registry outside a `registerPack` transaction. Reject primary pack registration if the registry was populated directly before binding; no session can acquire an identity for untracked blueprints. The proving pack and test builder receive authored identities. A cameo may originate in another story epoch, but its imported pack declares the *target* registry epoch; no second epoch registry is merged into the first. The registry exposes the primary identity to the coordinator; imported packs do not change save identity. This models composition without a content fingerprint, which remains assigned to later registry-swap work.

The outer `SAVE_SLOT_SCHEMA_VERSION` advances to 2. New `SaveSlotWriteInput` and `SaveSlotEnvelope` require `packId` and `packVersion`; the in-memory, file and browser ports preserve them. The browser port also copies accepted input and returned envelopes at save/load boundaries: its current direct references let callers mutate the stored slot. The repository rejects an identity-free or unsupported old envelope. `SimulationCoordinator` checks at construction that its registry identity and requested epoch agree, stamps new saves from the registry, and checks all three identity fields before codec, slice, RNG or legacy publication. Pack version matches exactly. Earlier campaign saves under that same version remain valid regardless of their world tick; older pack versions have no upgrade path in this change. There is no legacy epoch-to-pack mapping. The owner confirmed that no real pre-change save requires conversion. The alternative of inferring identity from `epochId` cannot detect a different pack for the same epoch.

### 3. Entity IDs share one domain-safe token rule

Export a domain entity-ID validator from the registry contract: lowercase ASCII alphanumeric first, then lowercase ASCII alphanumeric, underscore or hyphen, 1–64 characters. `CharacterBlueprintSchema` applies it before initial entity materialization; `WorldStateCodec` checks every loaded entity map key, inner `entityId`, and their equality. `formatCharacterRootSemanticId` uses that validator rather than maintaining a separate character rule in application rendering. An invalid authored or loaded entity fails before the frame path; the current frame builder keeps its defensive formatting. The current code has no general runtime materializer, so the later presence work must call this validator when that path ships. The frame builder already calls defensive semantic-ID formatting each frame. This change adds no new per-frame validation; registration and load reject bad IDs before that existing defensive check is reached.

### 4. Listing returns structural and contextual diagnostics

`SaveSlotRepositoryPort.listSlots(expectedIdentity?)` returns a discriminated readable/unreadable result for each safe-named `.json` candidate, sorted by slot ID. Readable means **repository-structurally readable**, not guaranteed loadable into every coordinator. Readable entries retain metadata. Unreadable entries carry only a safe slot ID and a stable code: `invalid_json`, `invalid_envelope`, `invalid_snapshot`, `invalid_slices`, `invalid_legacy_state`, `unsupported_schema`, `missing_identity`, `epoch_mismatch`, `pack_mismatch` or `pack_version_mismatch`. Repository save, load and listing share structural checks for the full envelope, inner snapshot and inner/outer epoch/tick equality, plain-JSON custom-slice container and version map, and parsed legacy state; invalid direct save input fails before replacement. They do not run registry-specific slice schemas or migrations, which only the coordinator owns. An optional expected identity adds mismatch classification. The existing `GET /api/saves` route calls listing without a pack context, so it reports structural problems; no production list caller currently supplies expected identity. A future caller with a bound registry can request contextual reasons. It never exposes a filesystem path, raw parser message or token. Unsafe path errors remain fail-closed errors, not entries. `InMemorySaveSlotRepository` and the browser port return readable entries for accepted writes and implement the same optional context.

Classify deterministically in this order: unsafe path fails closed; invalid JSON; unsupported envelope schema; missing identity on the current schema; remaining invalid envelope; invalid inner snapshot (including inner/outer mismatch); invalid custom-slice container/version map; invalid legacy state; then expected epoch, pack ID and pack version mismatches in that order. A schema-one identity-free file is `unsupported_schema`. Preserve the same precedence in repository load and listing where the error categories overlap.

This changes the old metadata-only list contract deliberately: silent omission hid a corrupt slot from the owner. Listing cost is proportional to total candidate bytes and occurs on an explicit query, not on a frame. Focused tests will measure representative save/list costs on the current host and record the reference-Mac limit without a wall-clock assertion.

### 5. Repository completion is authoritative for save status

`saveToSlot` returns the committed envelope after `saveRepository.saveSlot` succeeds. It makes the following `save_slot` telemetry record best-effort and does not catch repository errors. This preserves truthful retry behavior when telemetry fails after a durable write. A failed load still validates and records before publishing, retaining its current atomic rollback behavior. An alternative of recording before persistence could emit a success-looking event for a write that never happened.

## Consumer and gate trace

G1: registered primary pack → `EpochModuleRegistry` identity → `SimulationCoordinator.saveToSlot` → domain codec and save input → in-memory/file repository → guarded HTTP PUT/GET and disk bytes → `SimulationCoordinator.loadFromSlot` → `WorldState`/RNG/slice/version reader; listing goes from file candidate → repository classification → `GET /api/saves` JSON. The browser composition supplies the same identity-bearing in-memory port but does not become a disk-load consumer.

G2: `registerPack` validates authored identity/imports and entity IDs, and bound registries reject direct registration; repository and codec treat JSON as untrusted; HTTP guard, path confinement, token/media-type checks and byte cap remain authoritative. G3: Zod parsing and migrations are save/load/list costs, with no new frame-loop work. G4: failed registration and load preserve previous registry or coordinator state; failed writes preserve prior slot bytes; telemetry failure cannot obscure a completed save. G5: the owned defects are `S3-03`, `S3-09-fields`, `S3-17-save`, `S4-10`, `S5-03` and `HXSLICE-TELEM-SAVE-01`; checked ledger transitions and reconciliation follow retained task proofs. G6: every delta scenario receives a named domain, coordinator, repository or guarded HTTP test ending at its stated consumer.

## Risks / Trade-offs

- **Strict snapshots expose previously hidden malformed data** → Reject before publication, identify the field, preserve the slot and permit repair/retry. Direct repository tests must use current identity-bearing world fixtures.
- **Breaking save envelope and list types affect several layers** → Change them in small green tasks; retain the existing route and only extend its JSON result. No old disk saves were found or requested for migration.
- **Browser in-memory slots currently expose mutable references** → Copy accepted input and save/load results so a caller cannot alter the stored snapshot after validation.
- **Whole-slot validation increases explicit list cost** → Measure representative sizes, keep listing off the frame path and record target-hardware uncertainty.
- **Primary identity does not fingerprint imported content** → Exact primary pack version gates load; content fingerprint reconciliation remains with `10-registry-swap-and-legacy`.
- **Repository listing cannot prove coordinator compatibility** → It validates every structure available without a registry and states its meaning; registered custom-slice validation remains an atomic coordinator load check.

## Migration Plan

Implement inward-out, keeping each intermediate commit compiling: codec and coordinator, registry identity, envelope propagation and enforcement, entity validation, then listing diagnostics. Use synthetic temporary save files for compatibility and corruption tests; no tracked or local `saves/` files need deletion. If a task fails, keep the last green commit and correct the task before owner approval. After delivery, new saves use envelope schema 2 and inner snapshot version 2; unsupported identity-free envelopes remain visible with a reason rather than being silently converted. Rollback to older code would not read new envelopes, so the release boundary is the reviewed change, not a reversible on-disk migration.
