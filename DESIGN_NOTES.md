Each heading carries one status mark: `shipped` (in code, or in force for a rule or a record), `partial` (some shipped, the rest planned) or `planned` (no code yet). Planned behaviour carries a `(planned: <roadmap id>)` mark. A planned section is planned unless a sentence in it is tagged `(shipped)`, which names existing code that planned text builds on. Distant features keep a short summary here and a `Detail:` pointer to a file under `design/`. Change ids live in this file, under `design/` and under `openspec/` only. Cross-references name sections by title, never by number. Root and section guides describe shipped code; planned behaviour remains here. Historical review evidence is retained unchanged under `reviews/`.

## Frame and pillars (partial)

### Pillars (shipped)

Owner pillars stated during the 2026-11-08 root-and-branch review. Everything below is read against them.

- **P1.** The engine, modules, content objects and 3D render UI are built as a strong, decoupled, epoch-agnostic framework. The owner and an agent can then add detail and colour collaboratively as they go. The underlying tech and mechanics in the design notes are wanted. Some rules should still be set early enough to guide how the architecture evolves.
- **P2.** There is no free-text player input. A large share of the surfaced text should come from local SLM / Hugging Face generation, not hand-crafted lines. The owner is happy to get help with authoring.
- **P3.** Each epoch has a new operative with their own new Ship and Drone crew, because that is how the Culture works. The new crew, and the loss of the previous one, are part of the fun.
- **P4.** Some feedback is meant to be indirect: the player pieces together related events, NPC behaviour and world outcomes.
- **P5.** Everything the review settles stays open to later change. Core model, rules spine and roadmap order are a direction with room to add and modify, not a frozen spec.
- **De-weighted:** scale versus solo-developer time, and the number of review gates.

## Rules spine and engineering rules (partial)

### Rules spine R1 to R8 (partial)

Eight architecture-constraining rules, set early so they can guide how the architecture evolves. Owner: accepts the 8-rule rules spine, leaving room to modify. No rule is enforced by a test yet. Each rule gives its subject, its status, and the test or lint that enforces it (or "to be written", with the change that writes it).

- **R1 One watch clock** (planned: 05b-1-watch-clock-and-time-spend). Campaign time is `elapsedWatches`, advanced only by `advance_watches`. `worldTick` is an effect serial and never time, scars record the watch, and every `*Ticks` field is renamed `*Watches` while it has no users. The decision record is in Clock and time. Enforced by a domain test that no blueprint field is named `*Ticks` and that scars carry a watch (to be written).
- **R2 Actor and cause on every effect** (planned: cm-act-envelope-and-rolls). Every effect travels in the Act envelope (see Core model, Act), a finished dwell commits an Act, and a behaviour returns `WorldEffect[]`. Selection logic stays in `06-utility-ai`. Enforced by a reducer test that an effect from a behaviour commit carries `causeActId` (to be written).
- **R3 Thread structure** (planned: cm-threads-and-pillars). A thread is a state machine over `omen -> simmer -> institutional_friction -> crisis_fuse -> resolution`, held in a `ThreadRuntime` slice, with at most one spine thread in `crisis_fuse` at a time. Its inertia is derived from its pillars (see Leverage Chain). Enforced by a `ThreadRuntime` transition test (to be written).
- **R4 Discovery has a referent and an observer** (planned: cm-observation-notebook). Discovery is tracked per observer as decaying evidence in the Observation table, and the global `discoveryLayer` becomes a derived view, with `set_discovery_layer` kept as a shim (see Core model, Observation). Enforced by an eval that a rival strike needs an Observation held by that rival (to be written).
- **R5 Emergency cardinality and fuse** (planned: cm-ledger-and-emergency for the runtime, 09-emergency-fuse for the fuse). `EmergencyRuntime` carries a `scope` and may hold more than one emergency; compounding applies to the scoped group, not to everyone. The fuse is later and is not pulled into the threads-and-ledger core step. Enforced by a reducer test that compounding leaves an out-of-scope entity untouched (to be written).
- **R6 Reject instead of throw** (planned: hx-reducer-and-frame-safety). A reducer rejects an effect with a reason code and returns an outcome, and unknown ids behave the same everywhere. The throw survives only as an authoring-time contract test. The shipped reducer still throws today (for example `spend_orbital_delta` on a `burn` outside `zenith`) until that change ships. **Pause and lab, one definition everywhere**: the player pause sets the single domain freeze bit (planned name `simulationFrozen`), so time freezes while effects still reduce and return outcomes. Lab mode (desaturation, free-cam, picking) is a `PlaySession` interface flag that also holds the bit. Free-cam keys are gated on lab mode, not on `isPaused()`. `hx-reducer-and-frame-safety` owns the bit and its acceptance. There is no second domain pause flag. Enforced by a reducer outcome test and a pause test (to be written).
- **R7 Resource ledger** (planned: cm-ledger-and-emergency). Stipends, funds and pressure stocks are `ResourceLedger` entries. Insertion spends Delta and requires `zenith`, and is rejected otherwise (planned: 09-delta-coupling-and-forecast). Pressure stocks get diegetic tells. Enforced by a ledger reconciliation test (to be written).
- **R8 Epoch-end reads both ledgers and the Observation table** (status: open). The ending reads `materialScars` and `veilScars` and the Observation table. What counts as a finished Epoch 1 is open (see Open, deferred and parked): the owner has not addressed it, and no definition of done is written.

**Standing rule: freeze extension** (planned: pre-05b-launch-validation). No new kind or effect without content that uses it. Settle the clock model before more time-bearing schema. No deletion. An arch test in the kind-table change guards it (see Launch validation, kind table and fixtures), not prose.

### Engineering rules (partial)

Rules that bind how the code is built, kept here so the security record is the first of them. Later engineering rules append here. The bridge lock, session preservation and verification gate are shipped; later engineering work retains its planned markers.

#### Bridge lock (shipped)

Delivered by `hx-ops-safety`. All existing telemetry, save-slot, stage and character API routes pass through one guarded HTTP middleware before body buffering or storage dispatch. It checks exact loopback Host/Origin at the actual listening port, the narrow absent-Origin fetch-metadata fallback, the method/path allowlist, and a current token plus JSON media type on mutations. Vite CORS shares that port-bound policy. Excessive streams are destroyed without waiting for the sender to finish, and storage operations reject symlink redirection through the shared confinement helper. Operational details and error responses live in `src/interfaces/README.md`.

The dev page supplies the token to the existing Stage Lab browser transport. Stage and callable character saves persist through HTTP and can be read back through GET; failed saves retain the edit and a readable status. The game still needs the later JSON pack loader to consume saved lab files (see Lab saves). Real tests on `127.0.0.1:0` trace page token → browser transport → disk → GET, and HTTP telemetry → current-log query. This is a browser-origin defense and single-writer storage boundary, not isolation from a hostile process running as the same OS user.

Future Sound Lab `PUT /api/audio-patches` (planned: 05a-sound-lab) and Pacing Lab `GET`/`PUT /api/pacing-profiles/:profileId` (planned: 05b-2-storylets-and-lab) must register through this guard when implemented. Those routes remain planned.

#### Verification (shipped)

Delivered by `hx-ops-safety`. The concurrent verification command and serial fallback cover the same quality checks. Commits run staged formatting/linting followed by full verification, with failures blocking the commit. Skill checks validate structure and YAML metadata rather than prose or model recommendations. The authoritative commands and process behavior live in `package.json`, `scripts/verify.mjs` and root `AGENTS.md`; cold/warm measurements and platform limits are in `openspec/changes/archive/2026-11-10-hx-ops-safety/verification.md`. The reference-Mac timing target is distinct from measurements on the development host.

#### Determinism, fixed step and phases (planned)

- **Seed scramble**: a world seed passes `splitmix32` before `SeededRandom`, so adjacent seeds give uncorrelated streams; a golden-vector test pins it. RNG held outside `WorldState` is replaced by the stateless keyed `roll(worldSeed, streamKey, counter)` (planned: cm-act-envelope-and-rolls).
- **Fixed step**: Clock 1 runs on a fixed `1/60` s step with an accumulator and capped catch-up, replacing raw-dt stepping. Tests split a frame's dt to prove the same result.
- **Golden run**: `hashWorldState` and a golden run through `runScenario`, with shuffled insertion order, throwing `Math.random` and `Date` stubs, a slice JSON round trip and a phase-order test.
- **One lint block**: a single ESLint determinism block covers domain, non-scene content and application, and bans `node:*`, `require` and non-literal `import()`. Today the guards are literal-only and application has none. When it ships, the `AGENTS.md` layer table gains `Math.random` and `Date.now` bans on the application row.
- **Interpolation seam** (planned: hx-fixed-step-tick): the accumulator keeps the previous `WorldState`. `RenderFrameBuilder` receives the previous and current poses, an `alpha` and a teleport marker, and lerps positions, shortest-arc yaw and the camera focus; teleports and room changes do not interpolate. It lands as its own commit, and the application README and `AGENTS.md` record it when it ships.
- **Phase order** (planned: hx-fixed-step-tick, hx-kinematics, hx-reducer-and-frame-safety): commands, watch, materialize, kinematics, cognition, commit, flush, pinned by a named `PHASES` order and a test, because phase order is the main determinism risk.
- **Move outcomes as data**: a move ends with `Arrived`, `Blocked` or `Interrupted` and a `residualDt`. A door closing mid-route no longer causes a silent doorway dwell, a retarget plans from the body's position and not the last waypoint, a zero-speed move is rejected, and a hop is measured in metres.
- **Frame safety** (planned: hx-reducer-and-frame-safety): the frame `try`/`catch` re-arms `requestAnimationFrame`, and `PlaySession.status` is recomputed per call instead of sticking. Section `AGENTS.md` updates ride the shipping change.

#### State, saves and pack identity (planned)

- **Slices**: frozen on write and shared on read. Today the store deep-clones on every read and write and appends in O(n); the target is O(1) append, guarded by frozen-output invariant tests. `StateSliceKey<T>` gains an optional `schema`, `version` and `migrate`, and a plain-JSON guard so a `Map` or `Set` cannot enter a slice.
- **Codec**: `WorldStateCodec` owns `snapshotVersion`, the Zod load, the migrations chain and the epoch check, replacing four copies of the world-state field list. A save round-trip scenario guards it, and each of its three parts is its own task with its own round-trip test.
- **Pack identity**: saves carry `packId` and `version`, and load checks the pack and the epoch. Decision: one registry per epoch, with cameo content only through an explicit import list. Fingerprint reconciliation is parked with `10-registry-swap-and-legacy`.
- **Entity ids**: one entity-id pattern check at load and at materialize stops a bad id throwing in the render loop, and `listSlots` reports why a slot is unreadable.
- **Save policy (owner decision)**: autosave at watch boundaries plus named manual saves. Loading ANY earlier save is allowed; the owner wants rollback. The notebook (the player's Observations) is part of the save, so loading restores the knowledge state of that moment. Keyed rolls (`roll(worldSeed, streamKey, counter)`) mean a reload does not reroll outcomes unless the player acts differently. An optional ironman mode is parked (`ironman-mode`). This is a gate before `cm-observation-notebook`.
- **Legacy clamp** (planned: hx-1-legacy-clamp-seed-scramble): a legacy mutation clamps to `[0, 1]` with a telemetry note instead of throwing, and the throw stays only as an authoring-time contract test. `sourceScarId` is checked against the scar set (planned: 05b-1-watch-clock-and-time-spend). Scars record the watch (R1). Accumulation across epochs waits for `10-registry-swap-and-legacy`. The shipping change updates the domain `AGENTS.md` legacy section.

#### Launch validation, kind table and fixtures (planned)

- `validateLaunch(pack, stages, visuals)` collects every error with ids and file hints, and runs in `PlaySession` and in pack tests. Shape validation before it uses an interim loader check (planned: pre-05d-renderer-shape) that `validateLaunch` then absorbs.
- The epoch-agnostic denylist is derived from the exported packs and moved into `tests/architecture`, replacing the hand-typed list. `defineModuleKind` replaces the closed 11-kind registry, with a ref table. The freeze-extension guard lives here: an arch test fails a new kind or effect that no content uses.
- The docs-truth check first covers root `AGENTS.md` only; the check that every `*Blueprint` named in a section `AGENTS.md` exists lands in `pre-05b-pack-source-of-truth`, after those files are rewritten. Test fixtures leave the content barrel, and the content `AGENTS.md` recipes are rewritten to working steps.
- **Lab saves**: lab JSON is the source of truth. Packs and stages are JSON, loaded and Zod-checked at runtime through `validateLaunch`, with no emitted TS, and the bridge writes only allowlisted, schema-checked files. Until the loader exists (planned: pre-05b-pack-source-of-truth), a Stage, Sound or Pacing Lab save writes JSON the game does not load: nothing reads `src/content/scene/stages/*.json` at run time.

#### Telemetry policy (partial; planned: telemetry-wiring)

- **As it is today**: the infrastructure NDJSON logger and rolling compactor exist. The `50` MiB active threshold triggers compaction but is not a hard cap: the retained recent window can exceed it. The compacted stream has a `500` MiB priority-eviction cap, so even high-signal events are not retained without limit. Supplied reasoning uses the optional `aiReasoning` field. The browser game does not feed them yet: it keeps an in-memory log. Session preservation is shipped: construction and explicit starts rotate prior files into numbered groups under `logs/prev/`, with configurable completed-group retention. ## Clock and time (partial)

### Loop cycles (planned)

Three nested cycles, each on its own clock. Owner: the cost of talking comes from the world.

- **Minute cycle (the room, Clock 1)**: the player walks, uses and talks inside one room at `60` Hz, and NPCs deliberate, move, dwell and cool down on room seconds. Nothing in it advances a campaign watch by itself. Reading a conversation chunk and an ambient line are free.
- **Session cycle (watches spent, Clock 2)**: the player spends watches on Committed Time-Spend Actions: holding office, resting or studying, waiting on a courier, travelling. On a watch boundary the world has moved on: NPCs have moved by watch (the presence function, not wall-clock beats), correspondence has arrived, stipends and fuses have run down, and the notebook holds what the player learned. Autosave lands at watch boundaries (see Save policy in State, saves and pack identity).
- **Epoch cycle (the epoch watch budget)**: one epoch is about `7–14` hours on the 7-Epoch default ladder (`epochWatchBudget`). It ends by reading both ledgers and the Observation table (R8, still open), hands the operative role to a new crew (P3) and exports `CivilizationLegacyState` into the next epoch.
- **Talking costs time** (planned: 07-dialogue-paging): a conversation is a fractional time-spend verb (the integer unit that makes this exact, a finer unit under the watch, a per-conversation cost, or a carried remainder, is an owner decision pending). `05b-1-watch-clock-and-time-spend` owns the verb and its budget, and `07-dialogue-paging` charges it once per conversation, so the verb is not dead code. This is the world's price for talking: while the player talks, the world moves on. Reading one chunk is free, and the conversation as a whole is charged once.

### Four clocks and the decision record (planned)

The planned four-clock contract is `SimulationTimeClocks`. Room embodiment examples include body/head rotation, reliquary-lamp drone micro-swings, and weather particles. Original room pacing examples include ~250ms perception pulses and ~8–12s local cognitive pulses; these are tuning examples within the human-paced phase design, not implemented perception scheduling.

Room time and watch time are separate clocks. A room runs `stepKinematics` at 60 Hz with `2–15s` deliberation, dwell and cooldown, which suits watching an NPC think, walk across a room at `1.4 m/s` and act. If macro plotlines, horse couriers, stipends and NPC evolution also ticked every `10s`, an Epoch (the `7–14` hour budget in Loop cycles: the `50–100 hours` campaign divided by N configured Epochs, `7` on the default ladder) would burn out in 15 minutes.

1. **Clock 1, 60Hz frame and room embodiment (`elapsedSimulationSeconds`)**: locomotion, door hinges, room acoustics, eavesdropping and live conversation (`2–15s` phase timers). It never advances macro calendar time, except that a conversation charges the talk cost once (see Loop cycles).
2. **Clock 2, campaign watch and Committed Time-Spend (`elapsedWatches`)**: monotonic integer watches (`watchesPerDay`, `daysPerSeason`, `epochWatchBudget`) advanced by **Committed Time-Spend Actions**: holding Office court/audits, resting/studying in Chambers, waiting on or expediting correspondence, or taking an Epoch 2+ travel vignette (`06c-epoch-travel-vignettes`).
3. **Clock 3, storyteller and plotline point-release director (`StorytellerPacingDirector`)**: evaluates on `elapsedWatches` advances to meter **Butterfly Thread point-releases** (the thread machine of R3), rival escalations and **Compositional Storylets** (`StoryletTemplate` slot grammar, which `06a-interpersonal-regard-and-romantasy` extends with `RegardGraph` bindings).
4. **Clock 4, slow-drift NPC and social evolution**: closed-form per-watch / per-season drift on NPC `drives`, passive `Regard` cooling/grudge decay, `InertiaPillar` hardening (`Ignorance/Debt` early -> `Doctrine/Constituency` late) and career rank progression.

**Clock decision record (revisable).** `elapsedWatches` lives on `WorldState` and only one `advance_watches` effect advances it. `worldTick` stays the effect and telemetry serial and is never time. Scars record the watch, not `worldTick`. Every `*Ticks` field (`stipendPerTick`, `baseTransitTicks`, `fuseTicks`, the orbital phase durations, `burnCostPerTick`, `orbitalOffsetTicks`) is renamed `*Watches` while it has no users; `05b-1-watch-clock-and-time-spend` does the rename, and `storytellerMinWatchScale: 0` joins `FAST_EVAL_PACING_CONFIG` with `05b-2-envelopes-and-gates`. The four-clock shape is kept. Clock 1 runs on a fixed `1/60` s step with an accumulator (see Determinism, fixed step and phases). Rule R1 states the rule and its test.

## NPC minds and belief (partial)

### Cognition phases and cascade guardrails (partial)

- **Human-paced cognitive phases**: although the CPU scores utility in `<1ms`, NPCs think, move and act at a human pace in live play. Every `BehaviorModule` defines `deliberationSeconds` (thinking pause before moving), `dwellSeconds` (time physically performing the action at the waypoint before its `WorldEffect` commits), `cooldownSeconds` (recovery after acting) and `requiresExternalTrigger` (the NPC decides, then pauses in `awaiting_trigger` until the next player-created or macro-world trigger instead of speed-running a plot chain). The phase order of a step and the move outcomes that end a dwell are in Determinism, fixed step and phases.
- **Anti-thundering-herd NPC-to-NPC cascade dampening**:
  1. **Digestion delay and exponential hop backoff (`cascadeHopCount`)**: when NPC A triggers NPC B (`enqueue_npc_stimulus`), the stimulus is queued with a digestion delay of `baseDigestionSeconds * backoffFactor^hopCount`. At `maxAutonomousCascadeHops` (default `2`), propagation pauses in `awaiting_trigger` until a player or macro-world beat occurs (`release_external_trigger`).
  2. **Round-robin token-bucket evaluation (`maxCognitiveEvaluationsPerPulse = 1`)**: `SimulationCoordinator` staggers evaluations via `cognitiveRoundRobinCursor`, so at most one NPC transitions into `deliberating` per pulse and NPCs cannot stampede in sync.
  3. **Stimulus cap** (planned: cm-act-envelope-and-rolls): the queue cap evicts by priority and then age, with dedupe of repeats, so a flood of low-priority stimuli cannot push out a high-priority one. The Act record and keyed rolls of the same change are in Core model, Act.
- **Embodied cascades versus information diffusion** (planned: cm-diffusion-and-balancing): the 2-hop cap governs embodied NPC-to-NPC cascades in a room and stays. Information that travels between people (a rumour, a report, news) is diffusion: closed form, advanced per watch, never driven by wall-clock beats (which would break pause and punish reading). The cost of talking is in Loop cycles and is not a beat.
- Pacing parameters and the fast-eval override are in Clock and time, Pacing config and fast-eval override.

### Belief and deliberate misbelief (planned)

Belief maths are integer maths, with no decision model in the simulation path (see Text pipeline, AI notes). Learning stays offline.

- **Combiner**: belief on an Observation is an integer fixed-point noisy-OR. Parents that share an origin or channel collapse before combining. A spoof is a separate negative term. An order-independence test and a parent cap guard it, and each step carries a reason tag so the notebook can show why a rumour is strong. All of this is decided before the Observation schema freezes.
- **BeliefView**: NPC considerations read the actor's branded `BeliefView`, never world state. A contract test catches omniscient reads.
- **Utility** (planned: 06-utility-ai): NPCs use belief-conditioned utility terms. Expected-utility planning is for rivals only. Low confidence maps to investigate or wait. The vertical slice does not yet condition NPC utility on belief.
- **Deliberate misbelief (P4)**: NPCs acting on stale or spoofed beliefs are the readable mistakes that P4 depends on.
- **Offline learning only**: tuning keys and tables are fitted from deterministic self-play and committed as data tied to the rules hash, so a rule change invalidates them. Player style is tracked with counters, and tuned offline only.

Lines are grounded in NPC epistemic memory, drives, contradictions, cadence, and banned lemmas, never generic chatbot prose.

The timing-spike-gated local generation adapter is planned around `@huggingface/transformers` and a local `./public/models/` cache; neither is a shipped dependency or setup command.

- **The retired intent parser**: the three-stage intent parser (a lexical extractor, a MiniLM embedding worker and an intent combiner) is retired, since with no typed input there is nothing to parse. Its jobs are re-homed, not dropped. Negation and speech-act extraction served free-text parsing and go. Rival tells are applied by a deterministic `tellProfile` post-pass over rival lines, and gate tier 3 checks it (see Rivals). `CharacterBible` and `RegisterCard` are the authoring-kit inputs, `VoiceProfile` is the blueprint-side data the gate reads (cadence, tics, banned lemmas), and `tellProfile` is its rival-only part (planned, revisable). ### Conversation paging and ambient lines (planned)

Ambient lines and the per-conversation talk cost land in `07-dialogue-paging`; tone blips, `readingSpeed` and captions in `07-bubble-lace-skins-and-tone-blips`; the capture and return camera stack in `07-camera-directive-stack`.

A conversation the player enters, or that a world event pulls them into, can be long. Space advances it one readable chunk at a time. Speech the player did not enter (a market exchange, a passer-by's exclamation, the impatient beat in Direct floor locomotion) is an ambient line: colour, not a conversation. Paging depends on the menu stack and `interactionHold` in Proximity use and menus; the floor change only emits the impatient trigger.

- **A conversation**:
  - The first chunk is on screen at open. The Space that started the conversation does not also advance it (a world-opened conversation has no such press, so the next Space advances), and a held Space stays on the chunk showing; a new press moves on. Space on a chunk that shows the end mark exits the conversation (owner: "space exits the dialogue from the last chunk"). WASD does nothing while a chunk is showing. Escape on a chunk leaves the conversation and confirms nothing, and the top modal layer consumes that press so it does not also open pause.
  - A chunk is at most two wrapped lines, about `120` characters. The author splits an authored chunk, and it fails at pack load if over the cap; the text port measures and splits generated or templated lines the same way (gate tier 1). The page shows a continue mark or an end mark.
  - When a response is expected, the chunk stays up and a choice menu appears. W and S move the highlight (A and D are aliases), Space selects the row, and the talk continues with the next chunk or finishes. Escape on the choice menu pops that one layer, as in the menu grammar, and confirms no row. Leave is a row when the talk can end there. The press that reveals the rows does not also select one.
  - An NPC's lines use the diegetic bubble; an advisor's lines, including `AdvisoryDuel`, use the lace page, with the same keys. A second conversation opened over one sits on top, and finishing it returns to the one underneath. Only the embodied person being talked to is held: everyone else keeps walking, and another NPC can still emit an ambient line and slide the player.
  - Reading one chunk costs no watch; the conversation as a whole is charged once (see Loop cycles). A shown chunk is the line `ConversationHistory` keeps; the unread tail is not. A person with no authored line still opens the empty presenter and its Leave row.
- **An ambient line**: one short line on a speaker the player is not in conversation with. It expires on its own, takes no input, does not lock the player's feet and offers no choice; Space still uses whatever is in front of the player. Interacting with that speaker clears the line and opens a conversation if one is authored.
  - A market exchange is several ambient lines in order, each anchored to its speaker; a passer-by can fire one, and the impatient beat is the same primitive. Words come from the text port (authored, pooled or templated); the simulation composes no free text.
  - A line shows only when its speaker is audible under the earshot rule (the audibility tiers in Audio): distance, the room, and whether a door is `open`, `ajar`, `closed`, or `barred`. One line per speaker, and only a few on screen at once; a line tied to a blocked arrival keeps its slot and extra colour waits. An ambient line spends no watch, and is written into the notebook as a record, not replayed.
- **Contracts**: `ConversationPage` on the session menu stack holds an anchor id, the chunks, the index and any choice rows. Domain never sees key names, and a choice that changes the world dispatches a `WorldEffect`. `AmbientLine` is an anchor id, one string and a lifetime. Content registers the triggers: the floor change registers the blocked-arrival trigger, and later packs register overheard exchanges and exclamations. The pager has no epoch in it.
- **Left out**: a back-page and transcript on screen, a typewriter, speech audio, camera grabs.

### Direct floor locomotion (planned)

The player walks the floor instead of clicking a waypoint. NPCs stay on `requestWaypointMove` and `stepKinematics` (both shipped). It builds on the shipped walk and play shell, slots before the sound lab and pacing lab, and does not advance watches, spend storyteller budget or open an `AudioContext`.

- **Input and walk** (planned: 05d-input-and-control-frame):
  - WASD moves the focus body at its `walkSpeedMetersPerSec` (shipped field). W is into the picture, taken from the control frame (the active camera volume's yaw, pitch and distance) and latched while a move key is held, so a volume boundary does not turn the held direction. One yaw-neutral zoom-out scalar gives the single further-out view.
  - W or S with A or D is a diagonal: the steer is the sum of the held directions in the control frame, normalised, so a diagonal keeps the same speed. Releasing the keys stops the body that frame. A and D with no W or S turn in place at `yawSpeedRadiansPerSec` (shipped field) without sliding, and facing holds when the keys come up. A floor click moves nobody.
  - Owner decision: facing follows the walk direction, so while walking the body faces its steer. The proximity-use arc measures from that facing (see Proximity use and menus).
  - An `InputState` folds into an `InputFrame` each frame. `keyup`, `blur` and `visibilitychange` are handled so a lost key cannot leave the body walking. Keys are read by `event.code`; held and pressed sets feed a data action table. Space is edge-triggered with no auto-repeat, and the dev HUD is neutralised so Space cannot re-click it.
- **Floor and footprints** (planned: 05d-locomotion-footprint):
  - The floor is the stage footprint inset by a body radius of `0.22` m, and another embodied body is a disc of that radius. A prop blocks the oriented footprint of the mesh the kitbash builder draws for it plus `0.03` m so the body does not sit in the pixels. The proving-slice meshes are the exemplar, not the rule: a door leaf `1.2` m by `0.14` m and a crate `0.9` m on a side, times the prop's scale and yaw. The step tries X, then Z, and drops a step that would leave the floor or enter a disc or footprint.
  - The shipped hinge yaws the centered leaf in place (`open` adds a quarter turn, `ajar` adds `0.38` rad) without moving the pivot, so the proving-slice doorway stays covered. The locomotion change moves the pivot to the leaf edge so an `open` or `ajar` threshold clears; a `closed` or `barred` leaf stays across it.
- **Portal hop**: within `0.5` m of a portal's near waypoint, steering toward the far waypoint, an `open` or `ajar` portal hops the body one step inside the target space and the shell swaps the stage. A `0.4` s lockout stops doorway swapping every frame. `closed` and `barred` do not hop. Epoch 2+ travel stays a committed cabin, not a floor edge.
- **Arrival hold** (planned: 05d-arrival-hold-readability): only the player's disc blocks an NPC arrival, and another NPC on a mark does not block a snap. The NPC holds short of a target point the disc covers and the arrival does not commit. The timer starts when the NPC is held short and runs while the disc covers the point (sidestepping on the mark does not reset it). At about `6` s it emits an impatient ambient line (see Conversation paging and ambient lines); at about `12` s the player is slid out along the away vector, on the floor and outside props and bodies, and the NPC arrives. If the slide has nowhere legal to go, the NPC stays and the beat can repeat. One waiter shows the line: the NPC whose current target lies inside the disc. This change owns the wait, trigger and slide; varied wording belongs to paging.
- **Camera capture** (planned, later: 07-camera-directive-stack, after the pager): owner: "the camera should move with the players charachter centred, but we should leave the option open for certain world events to capture that centring, to show action, before automatically returning the camera to the player. we should research best practices/improvements/suggestions on this". The capture and return directive stack follows these rules: Space never skips a capture, movement or Escape hands control back, no capture opens during a conversation, `reduceMotion` cuts instead of gliding, and each capture has a maximum hold.
- **Contracts**:
  - `locomotionMode: 'waypoint' | 'direct'` on the character blueprint, default `'waypoint'` (planned: 05d-locomotion-footprint; not in the shipped blueprint, and the kinematics split depends on it). The proving-slice operative is the content exemplar set to `'direct'`.

The dev HUD waypoint command (shipped) stays for waypoint-mode bodies and tests, and on a direct body, while unpaused, it does not dispatch.
  - Application passes floor slabs and prop footprints in as plain rectangles (domain does not read meshes). A content shape descriptor `{ primitive, dims, offset }` feeds the renderer and the footprint builder (planned: pre-05d-renderer-shape). Its vocabulary starts as `box`, `cylinder`, `cone` and `icosahedron`, an unknown shape id fails validation (an interim loader check that `validateLaunch` later absorbs), and it carries the `surface` attribute footsteps need.

### Proximity use and menus (planned)

The player walks up to a prop, a portal or a person and presses Space, and the same keys drive every menu. It builds on the play shell and direct locomotion. Dialogue wording, interruption and pretexts stay in their own changes; the menu stack leaves a slot they fill.

- **Use** (planned: 05e-modal-stack-use-and-menu): Space uses the nearest point of a prop footprint, or of a person's disc, within `0.4` m and inside a `90°` arc centered on facing (`±45°`; facing follows the walk direction, see Direct floor locomotion). Of the things in reach, the one closest to straight ahead wins, a tie goes to the lower id, and nothing in the arc does nothing. The winner's name is the prompt, with a warm mark so the `0.4` m and `±45°` rule can be read. A global "important" accent is rejected because it would break P4.
- **Menu grammar**: while any menu is open the body stands still. W and S move the highlight, Space confirms, and Escape goes back one layer (owner: "escape to quit the menu/dialog"). A and D alias previous and next in a vertical list and own left and right in a horizontal row; the arrow keys are a second binding set. The top modal layer consumes every Space and Escape press in the frame it happens, so a press that opens a menu never also confirms a row and key repeat never confirms or pops twice. A movement key still held when the menu closes does not steer until released.
- **Doors, props, people**: a door opens rows for `open`, `ajar` and `closed`, and confirm calls `requestSetPortalState` (shipped); `barred` is shown and confirm writes nothing. Walking through an `open` or `ajar` door stays the portal hop. A person opens an empty presenter with Leave on it. A prop with no authored rows is not a target, and confirm on a prop row dispatches the existing prop-state effect (`update_prop_state`, shipped).
- **Pause**: menus do not pause the room, so a door confirm can dispatch and other bodies keep walking. Escape on an empty stack opens the player pause menu in the diegetic layer, with Resume as the default row. It freezes the room through the existing paused bit (shipped), leaves the camera anchored, and neither desaturates the picture nor frees the camera (the bit: R6). `F3` and backtick stay the lab and are ignored while a menu or that pause is up.
- **Contracts**: `selectProximityTarget` is a pure function over plain candidates, the menu stack lives on the session, and domain never sees key names. `interactionHold` lives on `WorldState`: `{ targetKind: 'entity' | 'prop', targetId }` or empty. Opening a person or prop sets it and closing the menu clears it.
  - A held person does not advance a path, run the impatient timer or slide the player. A held prop refuses any other writer until the player confirms or backs out, though the player's confirm still applies.
  - A door menu does not hold a passer-by, so their impatient timer keeps running. A menu opened on the waiting person holds them, and the timer restarts if the disc still covers the mark when the menu closes.
