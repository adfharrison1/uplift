# Document integrity procedure

Execute this procedure for every documentation edit under the delivery or periodic review workflows. It governs placement and evidence; it does not authorize additional edits or replace owner approval.

1. **Place by system and authority.** Read the owner's accepted words, current pillars/rules spine, `DESIGN_NOTES.md` and its “Where facts live” table. Identify the canonical home before writing: shipped code guidance in root/scoped README and AGENTS; design intent in DESIGN_NOTES or indexed `design/` files; ordered work in `openspec/roadmap.yaml`; proposal contracts under `openspec/`; review dispositions in the review register or finding inventory. Keep one canonical statement per concept and use pointers elsewhere. AGENTS capability claims accompany the work shipping that capability; design-only amendments do not rewrite AGENTS.
2. **Preserve meaning and status.** Carry owner language and exemplars verbatim. Mark shipped, partial, planned, parked and owner-pending content accurately. Preserve valid planned material; do not delete it merely because code is absent. Check new decisions against the pillars and rules spine; record conflicts for the owner instead of settling them silently. Research an unfamiliar named tool or technique before interpreting it. Validate external factual claims against primary sources.
3. **Maintain the navigation and decisions.** On every edit check the status index, Where-facts-live table, roadmap row and disposition row. Update each affected entry or explicitly record “unchanged” and why. Every new design feature file has a status-index row; the `design/README.md` navigation index is exempt. Verify links and ownership; do not invent decisions to close gaps or remove failed, undecided or unprocessed inbox text.
4. **Prove no loss before moving or cutting.** Map each old paragraph/block to its retained location, merged canonical statement or explicitly superseded owner decision. Preserve every unique concept, number, identifier and exemplar. Obtain independent fidelity/no-loss and coherence reviews before cutting config context or applying a restructure. Use verbatim text anchors rather than stale line numbers; after each batch refresh citations. Keep approved content batches separate from the later organizational pass.
5. **Check budgets and duplication.** Root AGENTS targets about 900 words, with a 1,050-word ceiling; config context stays below 1,500 whitespace-delimited words. DESIGN_NOTES has an aspirational roughly 14,000-word target, not a failing hard ceiling; the existing larger baseline is accepted. Put overflow in a focused indexed `design/` file rather than deleting meaning. The engineering split remains deferred until the first milestone is delivered. Report pre/post counts and any staged migration debt honestly; do not claim an unimplemented budget check exists. Read versions from `package.json` and `.nvmrc` rather than maintaining another version/CVE table.
6. **Review the result twice.** Give two independent reviewers **high reasoning, medium-to-high model** briefs: fidelity against exact accepted wording, coverage/order and no-loss map; coherence against the resulting docs, status, links, budgets and untouched sections. In delivery work these lenses may be included in the two task-review briefs when they receive the required inputs and remain independent. Verify their findings, fix confirmed issues and rerun checks before the applicable owner checkpoint. Run `npm run verify`; run strict OpenSpec validation when proposal contracts changed. Keep a concise integrity record listing placements, navigation checks (including unchanged), wording/traceability results, reviewer dispositions and measurements.

Historical review output is retained as evidence and is not rewritten to satisfy current guidance. Keep new live OpenSpec change citations in `openspec/`, `DESIGN_NOTES.md` or `design/`; root/scoped README, AGENTS, source and tests describe capabilities instead. Review findings remain under the tracked review-history convention accepted for this workflow.
