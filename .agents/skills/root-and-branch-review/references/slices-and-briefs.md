# Scout and challenger contracts

## Common brief

Every dispatch includes **high reasoning, medium-to-high model**, the review root and output path, a distinct lens, owned in/out-of-scope files, baseline references, the register index and binding owner pillars. Use repository-relative paths, not the historical author's checkout. State the project's current local/offline and reference-hardware constraints. Refresh facts rather than copying old counts.

Ask 4–6 concrete questions. Require at most eight ranked findings, at least two unconsidered routes, a keep list and a could-not-verify list. Findings must be falsifiable against this repository, quote exact evidence and state `bites_when`; generic best-practice advice without a concrete consequence is rejected. A finding with no near-term trigger belongs in the parked list with a revisit condition. Scouts work independently and cannot inspect each other's reports.

Owner pillars are binding until the owner revises them. Read them verbatim from the current register and design home. De-weighted topics are scale versus one developer's time and the number of review gates: neither is a finding's core argument. A gate-effectiveness finding requires numeric evidence and aims to make existing gates catch concrete defects. P5 makes accepted directions revisable, not permission to silently re-argue or replace them. If a disagreement touches an owner rule, carry it to the checkpoint.

JSON output has `findings`, `keep`, `unconsidered_routes`, and `could_not_verify`. Each finding carries `id`, `slice`, `topic`, `kind` (problem/risk/gap/overbuilt), `claim_kind` (rule/vocabulary/placeholder/code), `claim`, `evidence`, `bites_when`, `severity`, `confidence`, `disconfirm`, `recommendation`, `fix_cost`, `ignore_cost`, `relates_to`, and `status`. Tag claim kind separately from finding kind; placeholder art alone must not drive the roadmap. Each keep item cites evidence. Each route has an ID, title, proposal, rationale, reference game/technique where substantiated, and `replaces_or_changes`. See [evidence format](evidence.md) for quotation syntax.

`disconfirm` records what was checked that could refute the claim. A code bug includes a concrete failure scenario and a scratch reproduction where feasible. Report measurements with machine/context and scaling; absolute milliseconds are indicative off the reference machine. Research unfamiliar owner-named tools before guessing, and check external facts against primary sources. Record unavailable browser/GPU evidence honestly.

## Slices and scout lenses

Use two or three scouts per slice; when three lenses are listed use three to preserve independent ownership. Adapt file names after baseline inspection while keeping the responsibilities covered.
