# Agent Guide — Test Suites (`tests/`)

## Strict Guardrails (Enforced by `npm run verify`)

1. **Never Weaken Architecture Tests**: Never disable or relax assertions in `tests/architecture/layer_boundaries.test.ts` or `eslint.config.mjs` to make a failing build pass. Fix the offending import, lint error, or type annotation instead.
2. **Fast & Deterministic Unit Tests**: Unit tests (`tests/unit/`) and architecture tests (`tests/architecture/` — linear $O(N)$ file scan) target under three seconds on the reference Mac, without requiring a browser WebGL context or model loading. Record measured timings; do not add wall-clock assertions. Inject `SeededRandom` with fixed numeric seeds and `fixedTelemetryClock` for timestamps, use `InMemorySessionTelemetry`, `InMemorySaveSlotRepository`, and `InMemoryDomAttributeSink` for headless unit tests, and use `FAST_EVAL_PACING_CONFIG` when testing multi-step cognitive lifecycles.
3. **Isolated Temp Directories for Disk Tests**: Any test exercising `NdjsonSessionTelemetry`, `FileSaveSlotRepository`, or `handleLocalDiskBridgeRequest` disk routes must use `mkdtempSync(join(tmpdir(), '...'))` and clean up in `afterEach` so tests never pollute `./logs/`, `./saves/`, or `./src/content/scene/`.
4. **Zero `any` & Zero Non-Null Assertions (`!`) in Tests**: Explicit `any` (`: any`, `as any`, `<any>`) and non-null assertions (`!`) are banned in `tests/` just as in `src/` (enforced by ESLint and `layer_boundaries.test.ts`). Use strongly typed test helpers, explicit `undefined` guards, Zod schemas, or `unknown`.
5. **Pre-Commit Verification**: Always run `npm run verify` (concurrent format, lint, types and one architecture/unit test run) before committing any task.
6. **Content exemplars stay in content**: A headless content test may register a pack on `SimulationCoordinator` and step it with `FAST_EVAL_PACING_CONFIG`. Do not copy that pack's space, character, or prop ids into `src/domain/` or `src/application/`.
7. **Keep fast verification local**: The AI eval runner is planned in [design intent](../DESIGN_NOTES.md); no eval command is currently shipped. Do not introduce model loading or cloud inference into unit verification.

## Storage regression tests

Use real isolated directories for confinement and rotation tests. Inject selected failures through `LocalFileOps` while delegating other calls to `nodeLocalFileOps`; use a deterministic temporary-name supplier for collision/link tests. Never globally mock `node:fs`. Check outside sentinels, original/archive byte preservation, fresh current-query isolation and failed-instance write rejection. Cover constructor and explicit-start failures separately at each rotation transition, preserve pending groups across retry, and verify pruning/diagnostic failures leave current logging usable. Default retention is three completed groups; one writer owns each tested root.

For stage and character disk routes, pass trusted `LocalFileOptions` as the dispatcher's sixth argument to inject filesystem faults or a temporary-name supplier. Assert status plus real file readback, unchanged outside sentinels and previous asset preservation; cover GET confinement as well as PUT. Use a read-failure adapter to prove oversized files are rejected before being read. Direct dispatcher tests do not verify the HTTP trust boundary.

For browser save transport tests, exercise the real `createStageLab.saveStage` and callable `saveVisual` APIs. Check retained edits and persisted readback, not just header spies. Use actual Vite HTML transforms/restarts on `127.0.0.1:0` and an in-memory production HTML build to verify token lifecycle. Always close the dev instance and remove its temporary root, including on failure. Test the browserMain-owned status sink with repeated play-input synchronization; preserve its separate live-region attributes and verify explicit retry replaces the error. HTML-transform assertions alone are not HTTP authorization tests.

For HTTP authorization, mount the actual Vite plugin on an ephemeral loopback TCP port and obtain the token from served HTML. Configure shared policy CORS, explicitly supply browser-owned metadata in Node, and let the real browser transport supply its own token/JSON headers. Test successful writes through disk and HTTP readback as well as rejected requests through dispatch spies and unchanged storage snapshots. Raw `node:http` requests cover duplicate headers, byte counts, never-ended streams and aborts observed by the server. Cover root/parent/file/temp links, stable redacted failures (including 500 then 503 after failed session initialization), explicit recovery and retention override. Exercise actual Vite restarts with prior telemetry, archive bytes and fresh current queries; hold a partial HTTP body across restart to prove the retired run cannot dispatch. Include a real config factory that creates fresh policies, failed replacement followed by explicit retry, and concurrent restarts across successive server generations. Include session-start symlinks, with 400 followed by unavailable writes and explicit recovery. Keep normal-port policy tests synthetic so they never reserve 5173. Never bypass the guard for a test or silently skip loopback tests when sandbox socket permission is required.

## Verification tooling tests

`tests/unit/tooling/VerifyRunner.test.ts` runs controlled short-lived child programs through the real runner. Never recursively launch full verification from Vitest. Use process rendezvous to prove concurrent startup, explicit failures and bounded output for result handling, and PID-recording parent/grandchild fixtures for interruption. Verify descendants exit even when the parent exits first or ignores SIGTERM, and clean up all PIDs in teardown on failure. On POSIX the runner owns detached process groups; Windows uses `taskkill /T` then `/T /F`. Exercise the host's native behavior and use an injected process adapter for the other platform's command construction; record native-platform coverage limits with performance evidence. Hook fixtures use temporary Git repositories and stub only npm/npx commands; test successful commits, failure blocking and preservation of unrelated unstaged files.

Skill architecture checks enforce required `.agents/skills` files, matching name and nonempty description frontmatter, nonempty instructions, and the `.cursor/skills` prohibition. They do not pin prose headings or model recommendations. Preserve every layer, zero-any, determinism and documentation-link assertion when editing these checks.

For the portable review quotechecker, run `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests/tooling -p 'test_quotecheck.py'` separately from `npm run verify`. Use temporary roots and the real CLI; assert exit status, evidence diagnostics and unchanged outside sentinels. Preserve exact full-range/line semantics, traversal and symlink confinement, malformed-input rejection and command nonexecution coverage. Do not execute evidence commands in the checker or substitute source-text assertions for behavior. Skill changes need process-fidelity and cold-agent usability review against the actual workflow.
