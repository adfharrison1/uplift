# Test Suites (`tests/`)

## Purpose

`tests/` verifies architectural integrity, deterministic domain behavior, application simulation and rendering frame coordination, infrastructure persistence/telemetry, interface CLI/HTTP/Three.js/HUD adapters, plug-and-play content contracts, and headless multi-tick simulation stability with an under-three-second reference-Mac target as part of `npm run verify` (format, lint, typecheck and one combined architecture/unit Vitest run concurrently; `verify:serial` retains the sequential fallback).

The separate AI evaluation runner is [planned](../DESIGN_NOTES.md); no eval command or model runtime is currently shipped. Measure suite timing rather than treating the performance target as a test assertion.

## Test Tiers

- **`tests/architecture/`**: Static and structural verification enforcing inward imports, zero explicit `any`, deterministic domain/content code, section guides, tooling configuration and project skill metadata. Documentation truth checks resolve guide references, versions, numeric runner limits, design index and planned roadmap entries, budgets and live citation policy; they run shared roadmap and defect reconciliation in process.
- **`tests/unit/domain/`**: Fast, pure TypeScript unit tests for domain primitives, schemas, registries, kinematics, reducers, and Dual-Ledger civilization legacy (`SeededRandom.test.ts`, `StateSliceRegistry.test.ts`, `TelemetryAndSavePorts.test.ts`, `WorldStateCodec.test.ts`, `EpochModuleRegistry.test.ts`, `EpochModulePackIdentity.test.ts`, `WaypointNavigator.test.ts`, `Kinematics.test.ts`, `WorldEffectReducer.test.ts`, `CivilizationLegacyState.test.ts`). The kinematics and reducer suites use `tests/support/makeWorldState.ts` for synthetic entities and explicit world-state overrides.
- **`tests/unit/application/`**: Deterministic headless unit tests for application simulation coordination, PlaySession stage selection and controls, 3-Layer Visual Blueprints, and `RenderFrameBuilder` camera/NDC math (`SimulationCoordinator/`, `PlaySessionStage.test.ts`, `PlaySessionControls.test.ts`, `SceneVisualBlueprints.test.ts`, `RenderFrameBuilder.test.ts`). The coordinator's startup, simulation, save/legacy and versioned-slice suites cover waypoint requests, portal truncation, separation-weight spawn and rejection, atomic load failures, slice migration and real file repository readback. They use the synthetic epoch registry builder in `tests/support/makeRegistry.ts`, which supplies a primary test pack identity and explicit empty imports by default. Other synthetic packs must supply those fields too. PlaySession tests use the application-schema stage builder in `tests/support/makeStageBlueprint.ts`, retaining reduced-motion and stage-boundary assertions; the proving-pack content consumer remains in `tests/unit/content/`.
- **`tests/unit/infrastructure/`**: Real-directory tests for shared filesystem confinement, NDJSON session retention and failure recovery, rolling compaction, 50 MiB / 500 MiB storage budgets, and multi-session save/load repositories (`SafeLocalFiles.test.ts`, `NdjsonSessionTelemetry.test.ts`, `FileSaveSlotRepository.test.ts`). Faults use typed filesystem adapters and deterministic temporary names; tests check preserved bytes and unchanged outside sentinels.
- **`tests/unit/interfaces/`**: Unit tests for the `logs:query` CLI, Vite local disk bridge dispatcher schema/I/O behavior (telemetry, saves, scene blueprints, character visuals), Three.js chiaroscuro stage & kitbash builders, and `StageInspectorDomMirror` (`QueryLogsCli.test.ts`, `LocalDiskBridge.test.ts`, `ChiaroscuroStageRenderer.test.ts`, `StageInspectorDomMirror.test.ts`, `SceneBlueprintDiskBridge.test.ts`).
- The browser save-port suite (`BrowserSaveRepository.test.ts`) checks required pack identity and private input/return copies. File and coordinator suites cover old-envelope rejection, identity mismatch rollback and earlier-tick restore; real guarded HTTP save round trips and path checks remain in `LocalDiskBridgeHttp/storage.test.ts` and its sibling authorization suite.
- **`tests/unit/content/`**: Content contract tests. `StarterHoldStage.test.ts` registers the starter hold, crosses the open door, plans the return, and refuses a barred door. Exemplar ids in that test must stay out of `src/domain/` and `src/application/`.

Visual asset dispatcher tests exercise both stage and character GET/PUT against real isolated directories: linked or dangling roots/parents/files, linked or occupied temporary candidates, safe missing directories, malformed disk data, byte limits before reads, persisted replacement readback, and preservation after injected rename failure. These are in-process storage tests, not evidence of HTTP provenance or token enforcement.

`BridgeTransport.test.ts` uses a real Vite dev instance on an ephemeral loopback port to check HTML token injection and restart renewal, then a production HTML build to check token absence. It also drives stage and callable character saves through the transport into isolated disk repositories, covering failures, edit retention, explicit retry and ordered writes. `PlayInput.test.ts` exercises the page-owned save-status sink alongside input/frame synchronization, including live-region attributes and retained error text. These tests do not claim network authorization coverage.

`LocalDiskBridgeHttp/` splits the real loopback suite into authorization, storage and lifecycle tests around a shared test-only HTTP harness. It mounts the actual Vite plugin on `127.0.0.1:0`, retrieves the served token and sends proving-pack stage/character edits through the browser helper to disk and HTTP readback; synthetic stage inputs use `makeStageBlueprint`. It also exercises telemetry and save CRUD, a coordinator-produced custom-slice version sidecar through HTTP PUT/GET, disk readback and coordinator load, configured retention, initialization failure/retry, provenance/token/media-type rejection, duplicate headers, CORS, byte limits, no-end overflow, observed client aborts and filesystem links. Rejection checks include a dispatch spy and storage snapshots after legitimate startup rotation. Restart tests verify archived bytes, fresh current queries, configured retention and rejection of an old run’s in-flight body through both reused plugins and fresh config policies, including failed replacements and concurrent restarts; session-start link tests check 400, disabled writes and explicit recovery. Policy tests cover unbound/closed/restarted servers and the normal config's shared 5173 policy without reserving that port.

These tests need permission to open local sockets, including during `npm run verify`. All servers and temporary roots are cleaned up. Node does not supply browser provenance automatically: test adapters add Host/Origin or fetch metadata explicitly; the production browser helper itself supplies the token and JSON headers. Direct dispatcher tests remain storage/schema coverage only.

`tests/unit/tooling/VerifyRunner.test.ts` checks concurrent process startup, grouped output, failure/spawn-error propagation, output overflow, signal cleanup of real parents and grandchildren, complete PID publication, and Windows taskkill command construction through an injected adapter. It uses small fixtures rather than recursively running verification. Hook fixtures execute real temporary Git commits with controlled npm/npx responses and inherited foreign Git settings, verifying successful and blocked commits and preservation of the foreign repository and unrelated files. Native signal behavior is exercised on the current POSIX host; Windows command-construction coverage does not establish native Windows process behavior.

Architecture skill checks validate metadata and nonempty instructions while accepting prose/headings/model changes. Required files, the forbidden `.cursor/skills` location, section documentation and links, inward dependencies, zero-any and deterministic simulation rules remain enforced.

`tests/tooling/test_quotecheck.py` runs the periodic-review quotechecker as a real Python CLI against isolated temporary repositories. It checks complete multiline quotations, exact ranges and whitespace, physical line semantics, missing and escaping paths (including symlinks), malformed evidence and command nonexecution. Run `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests/tooling -p 'test_quotecheck.py'`. This targeted suite stays outside `npm run verify`, so ordinary Node verification does not acquire a Python dependency. Skill procedure changes also need independent process-fidelity and cold-agent usability reviews; text-matching tests do not establish agent behavior.

`tests/unit/tooling/ProjectStatus.test.ts` exercises the real module against isolated temporary Git repositories. It covers ordered/active roadmap selection, graph and archive identity failures, all legal and illegal transition edges, full history and immutable-provenance replay, evidence digests/tracking/Git references, stale revisions and shared locks, confinement, atomic-write failures, receipt relocation, interrupted cleanup, explicit cancel/resume/repair, recurrence and missing receipts. Receipt fixtures move synthetic directories directly; they do not invoke the archive wrapper or live OpenSpec state. Git fixture environments remove inherited `GIT_*` overrides and disable signing for their local fixture commit. Measure focused and full-suite durations; no wall-clock assertions enforce the reference target.

`tests/unit/tooling/ArchiveChange.test.ts` exercises the wrapper with real temporary Git/filesystem state and an injected CLI boundary. It checks schema-aware preflight, local-root rechecks, retained review digests, unsafe input/confinement, shared locking, prior-sync conflicts, CLI failures on either side of the move, every durable write boundary and idempotent cancel/resume/repair. Assertions end at receipt, roadmap, combined-list and reconciliation readback, including pending IDs, dated original identities and immutable original artifacts across direct recovery/reconciliation. Trusted phase callbacks inject failures; no command exposes them. A later-invocation regression proves scoped evidence/index batching does not reuse removed Git tracking. A separate retained smoke exercise runs the actual installed CLI in an isolated synthetic repository through spec synchronization, archive, listing, reconciliation and recurrence. Mock CLI fixtures alone do not establish installed CLI behavior.

The archive and project-status fixtures disable Git automatic maintenance per command before copying freshly committed repositories. Their cached templates are published only after a complete copy; injected copy failures propagate, remove the partial candidate and leave a later fixture usable.

Sync-proof regressions cover rollback after the move, partial output, retirement absence, missing proof, all recovery boundaries, builder input conflicts and compatibility failure on resume. Unit fixtures inject a trusted proof builder and do not require a global OpenSpec installation. Separate installed-CLI smoke verifies exact new/nested, CRLF, retirement, no-op and skip outcomes, actual rollback rejection and recovery without the CLI. Historical finalized receipts permit later main-spec changes; a remaining journal keeps outcome verification active.

The parallel-start fixture includes delayed worker readiness and waits for every worker to rendezvous. Its parent watchdog cancels the runner for cleanup; individual children do not impose a startup-speed deadline.
