# Test Suites (`tests/`)

## Purpose

`tests/` verifies architectural integrity, deterministic domain behavior, application simulation and rendering frame coordination, infrastructure persistence/telemetry, interface CLI/HTTP/Three.js/HUD adapters, plug-and-play content contracts, and headless multi-tick simulation stability in under 3 seconds as part of `npm run verify` (`format:check` -> `lint` -> `typecheck` -> `test:arch` -> `test:unit`).

AI subject cases are not a tier under `tests/`. They live in `eval/` and run with `npm run eval:ai`, outside `npm run verify`.

## Test Tiers

- **`tests/architecture/`**: Static and structural verification (`layer_boundaries.test.ts`) enforcing Clean Architecture inward imports, zero explicit `any`, ban on `Math.random()` / `Date.now()` in `domain`/`content`, presence/linking of hierarchical `README.md` and `AGENTS.md` files, ESLint/Prettier/Husky config checks, and `.agents/skills/uplift-debug/SKILL.md` plus `.agents/skills/uplift-design-notes/SKILL.md` verification.
- **`tests/unit/domain/`**: Fast, pure TypeScript unit tests for domain primitives, schemas, registries, kinematics, reducers, and Dual-Ledger civilization legacy (`SeededRandom.test.ts`, `StateSliceRegistry.test.ts`, `TelemetryAndSavePorts.test.ts`, `EpochModuleRegistry.test.ts`, `WaypointNavigator.test.ts`, `KinematicsAndReducer.test.ts`, `CivilizationLegacyState.test.ts`).
- **`tests/unit/application/`**: Deterministic headless unit tests for application simulation coordination, 3-Layer Visual Blueprints, and `RenderFrameBuilder` camera/NDC math (`SimulationCoordinator.test.ts`, `SceneVisualBlueprints.test.ts`, `RenderFrameBuilder.test.ts`). Coordinator tests cover waypoint requests, portal truncation, and separation-weight spawn and rejection.
- **`tests/unit/infrastructure/`**: Real-directory tests for shared filesystem confinement, NDJSON session retention and failure recovery, rolling compaction, 50 MiB / 500 MiB storage budgets, and multi-session save/load repositories (`SafeLocalFiles.test.ts`, `NdjsonSessionTelemetry.test.ts`, `FileSaveSlotRepository.test.ts`). Faults use typed filesystem adapters and deterministic temporary names; tests check preserved bytes and unchanged outside sentinels.
- **`tests/unit/interfaces/`**: Unit tests for the `logs:query` CLI, Vite local disk bridge dispatcher schema/I/O behavior (telemetry, saves, scene blueprints, character visuals), Three.js chiaroscuro stage & kitbash builders, and `StageInspectorDomMirror` (`QueryLogsCli.test.ts`, `LocalDiskBridge.test.ts`, `ChiaroscuroStageRenderer.test.ts`, `StageInspectorDomMirror.test.ts`, `SceneBlueprintDiskBridge.test.ts`).
- **`tests/unit/content/`**: Content contract tests. `StarterHoldStage.test.ts` registers the starter hold, crosses the open door, plans the return, and refuses a barred door. Exemplar ids in that test must stay out of `src/domain/` and `src/application/`.

Visual asset dispatcher tests exercise both stage and character GET/PUT against real isolated directories: linked or dangling roots/parents/files, linked or occupied temporary candidates, safe missing directories, malformed disk data, byte limits before reads, persisted replacement readback, and preservation after injected rename failure. These are in-process storage tests, not evidence of HTTP provenance or token enforcement.

`BridgeTransport.test.ts` uses a real Vite dev instance on an ephemeral loopback port to check HTML token injection and restart renewal, then a production HTML build to check token absence. It also drives stage and callable character saves through the transport into isolated disk repositories, covering failures, edit retention, explicit retry and ordered writes. `PlayInput.test.ts` exercises the page-owned save-status sink alongside input/frame synchronization, including live-region attributes and retained error text. These tests do not claim network authorization coverage.

`LocalDiskBridgeHttp.test.ts` mounts the actual Vite plugin on `127.0.0.1:0`, retrieves the served token and sends stage/character edits through the browser helper to disk and HTTP readback. It also exercises telemetry and save CRUD, configured retention, initialization failure/retry, provenance/token/media-type rejection, duplicate headers, CORS, byte limits, no-end overflow, observed client aborts and filesystem links. Rejection checks include a dispatch spy and storage snapshots after legitimate startup rotation. Policy tests cover unbound/closed/restarted servers and the normal config's shared 5173 policy without reserving that port.

These tests need permission to open local sockets, including during `npm run verify`. All servers and temporary roots are cleaned up. Node does not supply browser provenance automatically: test adapters add Host/Origin or fetch metadata explicitly; the production browser helper itself supplies the token and JSON headers. Direct dispatcher tests remain storage/schema coverage only.
